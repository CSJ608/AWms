# 界面规格：PC 全局布局与全局标签页（草案 v0.1）

> 状态：**草案 v0.1（2026-08-22，待设计评审）**。评审通过前不得修改前端代码。
> 适用范围：登录后的 Web/PC 工作台；PDA、独立登录页、全屏 404 不采用本布局。
> 基线：复用《视觉规范 v1.0》《通用列表与表单 v1.0》《入库管理 Web v0.3》；本规格将替代既有 Web 基线中的“左侧菜单 + 顶部上下文”全局框架描述，页面内部规格仍继续有效。

## 一、目标与设计原则

1. 用户可以同时保留多个工作面，切换菜单或业务标签不丢失正在处理的输入、筛选和分页。
2. 全局导航、菜单搜索、多语言和用户功能集中在一个稳定顶部区域，减少页面级重复。
3. 全局框架只承载导航与工作面，不承载业务上下文；页面标题、业务筛选和操作仍在内容栏。
4. 活动标签页状态属于全局应用层，不属于入库等单个业务模块。
5. 所有入口按权限过滤；无权限入口不出现，深链接访问显示 403。

## 三、顶部导航栏

### 3.1 左侧品牌区

| 元素 | 规则 |
|---|---|
| LOGO | 使用现有产品 LOGO；无图片资源时沿用当前包箱图标 + 主色底 |
| 产品名称 | 读取 `common.appName`；左对齐；最多显示一行并截断 |
| 点击行为 | 点击 LOGO/产品名称聚焦或打开默认首页标签，不刷新浏览器页面 |

### 3.2 搜索菜单

```text
初始：[搜索菜单 ICON]
点击：┌──────────────────────────────────────────────┐
      │ [输入框：搜索菜单]                         [关闭] │
      │ 工作台 / Workspace                          │
      │ 入库管理 / Inbound                          │
      │ 基础数据 · 物料 / Materials                  │
      └──────────────────────────────────────────────┘
```

1. 搜索图标常驻顶部右侧；点击后在顶部导航下方展开搜索面板，输入框自动聚焦。
2. 搜索范围为登录返回的 `menus.web` 与前端路由注册表交集，且必须通过 `route.<moduleCode>` 权限。
3. 匹配字段：菜单标题当前语言文案、产品代码内英文标题、`moduleCode`；本批不匹配菜单描述、路由路径和业务数据。
4. 输入实时过滤；结果显示菜单分组、图标、标题、模块名；为空时显示有权限的常用/最近菜单（最多 8 条）。
5. 键盘支持：上/下选择、Enter 打开、Esc 关闭；点击面板外关闭并保留下次打开时的输入内容。
6. 选中结果后：已有对应标签则聚焦，没有则打开；搜索面板关闭。
7. 搜索失败不调用后端；菜单数据缺失时显示“菜单加载失败，请重新登录或刷新重试”。

### 3.3 多语言切换

| 项 | 规则 |
|---|---|
| 入口 | 地球/语言 ICON，可显示当前语言短码（ZH/EN） |
| 菜单 | 悬浮或点击打开；键盘焦点也必须能打开 |
| 选项 | 中文（zh）、English（en） |
| 当前项 | 勾选/高亮，不可禁用 |
| 切换 | 立即更新 UI 文案，无需刷新页面；写入本地持久化 key |
| 请求 | 后续请求 `Accept-Language` 使用当前语言 |
| 回退 | 词条缺失回退中文；不允许显示裸 key |

语言切换只影响界面语言，不切换仓库、单据等业务上下文，也不自动重置活动标签页。

### 3.4 用户菜单

```text
[头像 LOGO + 王仓管 ▾]
┌────────────────────────┐
│ 王仓管                  │
│ wang01 · 仓管 / 系统管理员 │
├────────────────────────┤
│ 退出登录                 │
└────────────────────────┘
```

1. 头像 LOGO 使用用户名称首字符或后续头像 URL；名称缺失时显示 `?`。
2. 头像 + 用户名称常驻顶部；名称超长截断并提供完整文本提示。
3. 悬浮或点击打开菜单；菜单必须可键盘操作。
4. 菜单顶部展示姓名、用户名、角色，只读。
5. 本批用户功能仅提供退出登录；退出前不弹确认，退出后清理会话与标签状态并进入登录页。
6. 个人中心、修改密码、通知中心未定义契约，不显示“开发中”入口。

## 四、全局标签页栏

### 4.1 固定 ICON 与活动标签

| 区域 | 行为 |
|---|---|
| 标签页 ICON | 固定第一个位置；打开标签总览面板，展示全部活动标签，支持查找、切换、关闭单个标签和关闭其他标签 |
| 菜单 ICON | 固定第二个位置；打开全局导航面板，按 `groupKey/sort` 展示有权限菜单；选择菜单打开或聚焦标签 |
| 活动标签 | 固定 ICON 之后横向排列；显示图标（可选）、标题、可关闭按钮 |
| 当前标签 | 使用主色下划线/背景区分，且内容栏为对应路由 |
| 溢出 | 横向滚动；显示左右箭头；标签总览始终可访问全部标签 |

固定 ICON 不显示关闭按钮，不算活动标签，不参与最近使用排序。

### 4.2 标签状态模型

标签状态必须放在全局应用层，由统一的 Workspace Tabs 状态管理，不放在某个业务页面内部。

```ts
interface WorkspaceTab {
  key: string                  // 去重键：模块首页用 moduleCode；详情用业务资源 + ID
  routePath: string            // 当前路由
  titleKey: string             // 静态菜单/页面标题
  titleParams?: object         // 单号等动态标题参数
  moduleCode: string
  iconKey?: string
  closable: boolean
  dirty?: boolean              // 有未提交输入或需确认关闭
  lastActiveAt: number | string
}

interface WorkspaceTabsState {
  tabs: WorkspaceTab[]
  activeTabKey: string | null
}
```

1. 状态列表、活动 key、最近使用顺序由全局应用层持有；菜单导航只派发“打开或聚焦”。
2. 页面内部筛选、分页、滚动、表单草稿由各活动标签的保活实例持有。
3. 标签标题不缓存已翻译后的长字符串作为唯一标识；语言切换后用 `titleKey + titleParams` 重新渲染。
4. 会话恢复时若用户权限或菜单变化，打开标签需重新校验；无权限标签显示不可进入状态，不自动静默关闭。
5. 本批不做持久化到后端；浏览器刷新或新开浏览器标签只恢复当前路由对应的应用内标签。

### 4.3 打开、聚焦与去重

| 场景 | 规则 |
|---|---|
| 点击菜单首页 | key=`module:<moduleCode>`；已打开则聚焦，不重复创建 |
| 点击页面内“新建” | key=`<module>:create`；同一模块已有未提交新建标签时聚焦原标签 |
| 打开业务详情 | key=`<resource>:<id>`；同一详情已打开时聚焦并同步到最新路由 |
| 浏览器前进/后退 | 当前活动标签与路由同步，不创建重复标签 |
| 深链接 | 校验权限后恢复当前路由对应标签；无法识别时打开模块首页标签或 404 |
| 从搜索/菜单重复进入 | 仅打开或聚焦，不销毁已有标签 |

### 4.4 保活与关闭

1. 切换菜单、切换标签、打开搜索/菜单面板均不得卸载已有活动标签的工作面。
2. 保活范围是当前登录会话；用户退出登录后清空全部标签状态。
3. 关闭普通标签直接关闭；`dirty=true` 时弹出确认：`放弃填写 / 继续编辑`。
4. 关闭当前标签后聚焦最近使用标签；没有剩余活动标签时聚焦默认首页标签，不得显示空白工作区。
5. 关闭其他标签可批量执行；含未提交输入的标签需在总览中标记并在确认文案中说明数量。
6. 标签关闭后释放对应页面状态；再次打开同名入口按新实例初始化。
7. 本批不做拖动排序、固定标签、跨会话恢复和标签分组。

### 4.5 与入库模块的关系

1. 现有入库模块页面内“应用内工作标签”迁移为全局标签页栏承载；不得出现两层工作标签。
2. 入库页面内部的“入库单 / 收货记录 / 质检异常”是业务视图标签，保留在内容栏内部。
3. 入库列表筛选、分页、滚动，新建表单输入，单据详情上下文必须随全局标签保活。
4. 新建成功后原标签从“新建入库单”转换为单号详情，规则沿用《入库管理 Web v0.3》。
5. 其他业务模块接入时必须注册标签 key 与标题来源，禁止自行维护第二套工作标签数组。

## 五、内容栏

1. 内容栏只渲染当前活动标签对应的路由工作面；非当前标签保活但不参与可见焦点。
2. 页面标题、仓库选择器、业务筛选、表格、操作按钮、Dialog 均留在内容栏。
3. 内容栏独立滚动；切换标签恢复各自滚动位置。
4. 403、404、加载、空态在内容栏内展示，顶部导航和标签页栏保持可用。
5. 全局错误条用于影响当前标签的加载失败；提交反馈优先沿用 toast/inline/AlertDialog 规则。
6. 页面不得自带第二套顶部导航、侧边栏或工作标签栏。

## 六、多语言与显示规则

### 6.1 词条来源

| 内容 | 来源 |
|---|---|
| 顶部导航、标签页、菜单、按钮、表头、空态、前端校验 | 前端 `zh/en` 词条 |
| 后端业务错误 message | 后端 `messages.zh/en.json`，按 `Accept-Language` 输出 |
| 已定义枚举 | API 返回稳定值，前端按枚举 key 翻译 |
| 后端业务原因 | 契约应返回稳定 reasonCode；未定义前不得把中文说明当作前端分支依据 |
| 后端 message 展示 | 默认直接展示；前端可按错误 code 做静默、刷新或更强上下文提示 |

### 6.2 语言切换验收

1. 切换后顶部导航、菜单面板、搜索结果、标签页、内容栏、空态和错误兜底立即更新。
2. 切换语言不改变标签顺序、活动标签、筛选条件、表单输入和路由。
3. 切换后新请求携带 `Accept-Language`；不因语言切换主动清空服务端缓存。
4. 词条缺失回退中文，并应在开发/CI 检查中暴露，不允许界面显示裸 key。
5. 中英词条结构一致；动态标题使用插值参数，不拼接含业务值的整句词条。

## 七、状态矩阵

| 状态 | 表现 |
|---|---|
| 会话恢复中 | 顶部导航骨架；固定 ICON 禁用；内容栏显示全局加载 |
| 菜单为空 | 菜单 ICON 显示“暂无可用菜单”；搜索面板显示空态与重试入口 |
| 菜单加载失败 | 顶部保留品牌区与用户菜单；菜单/搜索不可用并提示重试 |
| 无权限 | 菜单/搜索不出现入口；深链接在内容栏显示 403 |
| 标签为空 | 自动聚焦默认首页标签；若首页无权限，聚焦第一个可访问菜单 |
| 标签溢出 | 左右滚动箭头 + 标签总览；不隐藏固定 ICON |
| 未提交关闭 | AlertDialog 确认，保留原标签和输入 |
| 语言缺失 | 回退中文；开发环境/测试暴露缺失 key |
| 会话过期 | 清空会话与标签状态，跳转登录页；登录成功后从默认首页重新开始 |
| 404 | 内容栏显示 404，可返回首页或第一个可访问菜单 |

## 八、视觉锚点

1. 顶部导航：白色/卡片背景、底部 1px 边框；品牌区、右侧功能区间距 4px 倍数。
2. 图标：统一 Lucide 20px；搜索、语言、用户三个入口均可识别并提供可访问名称。
3. 标签页栏：比顶部导航低一级的背景；当前标签主色下划线或主色浅背景；普通标签 hover 不改变布局。
4. 长标题：最大宽度固定、ellipsis、完整标题 tooltip；关闭 ICON 16px，命中区不小于 24px。
5. 内容栏背景沿用中性灰；页面卡片、表格、状态徽章继续遵循《视觉规范 v1.0》。
6. 禁用装饰性渐变、大幅动效和页面级阴影；标签切换只允许轻微过渡。

## 九、可访问性与键盘

1. 顶部三个功能按钮和两个固定 ICON 均为可聚焦控件，提供 `aria-label` / tooltip。
2. 搜索面板、语言菜单、用户菜单、全局菜单、标签总览使用 Dialog/Popover 语义，Esc 关闭，焦点圈不丢失。
3. 活动标签使用 `role=tab`、`aria-selected`；标签列表使用 `tablist`，左右方向键切换。
4. 关闭按钮独立可聚焦，Enter 关闭；关闭后焦点移向新活动标签。
5. 菜单搜索输入框自动聚焦；结果列表支持上下键和 Enter。
6. 颜色不是唯一状态表达；当前标签同时有位置、样式和 ARIA 状态。
