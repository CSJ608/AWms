# 界面规格：入库管理 Web（第 4 批视觉评审通过 v0.2）

> 状态：**第 4 批视觉评审通过 v0.2（2026-08-20）**。用户确认应用内工作标签及更新原型无异议；仍需契约双向评审通过后前端才可实现。
> 角色：仓管/主管。目标：在可切换且保留上下文的工作面内完成入库单准备、收货追踪和质检异常闭环。
> 基线：复用《通用列表与表单》、全局视觉规范与既有 Web 布局；不创建第二套页面框架。

## 一、信息架构

Web 主框架增加应用内工作标签栏；`/inbound` 页面内部再使用业务标签切换三个视图，保留左侧全局导航：

```text
工作标签：[入库管理] [新建入库单 ×] [PO-20260820-0003 ×]
=============================================================
入库管理
[入库单] [收货记录] [质检异常]
-------------------------------------------------------------
当前视图工具栏 / 筛选区
数据表格
分页
```

- 工作标签承载用户正在处理的任务；业务标签只切换入库模块内的列表视图，两者不得混为同一层。
- “入库管理”工作标签复用现有实例；新建和单据详情使用可关闭工作标签。
- 业务标签切换后，三个视图的筛选和分页状态分别保留。
- 页面不使用嵌套卡片；标题、工具栏、筛选、表格按垂直信息带排列。
- 默认进入“入库单”；深链接分别为 `/inbound/orders`、`/inbound/receipts`、`/inbound/exceptions`。

### 1.1 工作标签行为

| 场景 | 行为 |
|---|---|
| 从菜单进入入库管理 | 打开或聚焦“入库管理”标签，不重复创建 |
| 点击“新建入库单” | 打开并聚焦“新建入库单”标签；已有未提交的新建标签时直接聚焦原标签 |
| 在工作标签间切换 | 保留列表筛选、分页、滚动位置和新建表单输入 |
| 点击入库单行 | 按单据 ID 打开详情标签；已打开时直接聚焦 |
| 新建成功 | 当前“新建入库单”标签原位转为单据详情，标题更新为单号，不再额外打开第三个标签 |
| 关闭未提交的新建标签 | 提示“内容尚未提交”；提供“放弃填写 / 继续编辑”，本批不提供持久化草稿 |
| 关闭当前标签 | 聚焦最近使用的工作标签；不得把用户送到空白工作区 |
| 刷新或直接访问深链接 | 至少恢复当前路由对应标签；本批不要求跨会话恢复全部历史标签 |

- 工作标签是应用内部导航，不使用浏览器弹窗、`window.open` 或新的浏览器标签页。
- 标签标题需截断长单号并提供完整文本提示；关闭按钮使用熟悉的关闭图标并提供可访问名称。
- 本批只建设必要能力：打开、聚焦、切换、保活、关闭确认和路由同步；不做拖动排序、固定标签和跨会话恢复。

## 二、入库单视图

### 2.1 列表

```text
入库单                                      [新建入库单]
单号 [________]  类型 [全部]  状态 [全部]  仓库 [选择] [查询][重置]
-----------------------------------------------------------------
单号              类型  仓库   来源       状态        创建时间   操作
PO-20260819-0001   采购  WH-01  SUP-001   已确认      10:20     查看
```

- 常用筛选：单号、类型、状态、仓库；高级筛选复用 FieldMeta。
- 状态徽章：CONFIRMED/RECEIVING/RECEIVED/VOIDED，状态文字优先，颜色辅助。
- 行点击进入详情；操作列只保留高频命令，更多操作进入详情页。

### 2.2 新建

新建使用独立路由 `/inbound/orders/new`，并承载在“新建入库单”工作标签中；不得使用 Dialog，也不得在列表底部展开表单：

```text
新建入库单
类型 [PO/PR/OT]  仓库 [选择]  来源类型 [选择]  来源 [选择/填写]
-----------------------------------------------------------------
行号  物料 [ReferencePicker]  应到数量  [删除]
1     MAT-001                 200
[添加一行]
                                             [取消] [创建并查看]
```

- 至少一行；同一物料允许多行，但后续扫码必须通过 `orderLineId` 精确定位。
- PO 显示“采购收货必须先建单”的说明；PR/OT 既可预建，也可在 PDA 无单新建。
- 数量按 decimal 字符串提交；创建成功跳转详情，不自动打印。
- 切回“入库管理”时新建输入保留；再次点击“新建入库单”聚焦该标签，不清空也不重复创建。
- “取消”执行关闭标签流程；已有输入时必须先确认放弃。

### 2.3 详情

- 头部：单号、类型、仓库、来源、状态、创建人/时间。
- 行表：行号、物料、应到、已收、未收、唯一码统计。
- 操作：打印单据码、打印外标签、生成唯一码标签、作废。
- 作废使用 AlertDialog，原因必填；已收完/已作废时按契约禁用并显示原因。
- 打印均先打开预览；PDF 可下载/浏览器打印，失败不改变单据状态。
- 从列表打开详情时使用按单据 ID 去重的工作标签，允许同时查看多张不同入库单。

## 三、收货记录视图

- 列表列：收货单号、来源单号、仓库、状态、操作人、发生时间、照片数。
- 筛选：收货单号、状态、仓库、日期范围。
- 详情展示行级物料、批次、应到/实收/差异、质检/上架状态以及时间线。
- 照片以缩略图网格展示，点击查看原图；无照片时显示明确空态。
- 操作：打印/补打收货回执、预览批次标签；重打产生新的打印留痕，不修改收货状态。

## 四、质检异常视图

```text
质检异常
状态 [待处理/已处理]  仓库 [选择]  原因 [全部]  [查询][重置]
-----------------------------------------------------------------
收货单   物料/批次   数量   原因   照片   上报人/时间       状态
RCP-...  MAT-001     200   破损   2张    王仓管 10:40    待处理
```

- 行详情展示收货上下文、异常原因、备注和照片，不要求主管返回 PDA 查信息。
- “放行”对应 `PASS`：确认后转为可用并进入上架待办。
- “驳回”对应 `REJECT`：确认文案明确“货物继续留在暂存区且不可上架”；备注必填。
- 已处理记录只读展示处理动作、处理人、处理时间和备注。

## 五、状态矩阵

| 状态 | 表现 |
|---|---|
| 加载 | 表头稳定，行区显示骨架，工具栏不位移 |
| 空态 | 分别显示“暂无入库单 / 暂无收货记录 / 暂无质检异常”，保留可执行主操作 |
| 查询失败 | 表格上方错误条 + 重试；保留筛选条件 |
| 提交中 | 当前命令按钮锁定；其他行不受影响 |
| 并发变化 | `ORDER_STATUS_INVALID`/`VERSION_CONFLICT` 后刷新详情并提示最新状态 |
| 无权限 | 标签或操作按权限隐藏；深链接访问显示 403 状态 |
| 打印失败 | 保留业务成功状态，提供重新预览/下载入口 |

## 六、权限与交互

- 查看入库模块：`route.inbound` + `menu.inbound`。
- 新建/作废入库单、处理质检异常、打印分别受独立操作权限控制。
- 危险动作只使用文字明确的确认弹窗；图标按钮使用 Lucide 图标并提供 tooltip。
- 日期、数量和编号使用 tabular-nums；表格保持中等密度，长编号允许换行或省略并可悬停查看。
- 本页按桌面工作面设计，基准宽度 1024px；窄屏不与 PDA 作业页面合并。
- 工作标签与当前路由保持同步；浏览器前进/后退切换到对应工作标签，不创建重复实例。
