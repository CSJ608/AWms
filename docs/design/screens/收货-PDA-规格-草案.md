# 界面规格：收货作业 PDA（第 4 批视觉评审通过 v1.3）

> 状态：**第 4 批视觉评审通过 v1.3（2026-08-20，待契约复核）**。用户已确认扫码上下文、来源规则和唯一码数量行为；契约复核通过后前端才可实现。
> 角色：收货/质检/上架员。基线：数量步进 ±1 + 连扫累加（无 ×10）；行录入无"添加下一行"按钮（确认页可继续添加行）。

## 一、屏幕流

```text
主界面（我的作业）
  → ① 定位收货上下文（无单新建 / 扫预建单据二维码）
  → ② 选入库类型（仅无单新建：生产/其他；采购必须扫描预建 PO）
  → ③ 行录入（扫码区 + 当前行卡片 + 大数字键盘）
  → ④ 确认提交（行汇总 + 差异提示 + 拍照可选 + 继续添加行）
  → ⑤ 结果页（成功 + 打印回执 + 继续下一单）
```

## 三、扫描与输入规范（核心）

| 扫到 | 反馈 | 行为 |
|---|---|---|
| AWMS1 外标签 S | 绿 + 短音 | 定位物料并带出 `batchProps`；数量输入/连扫累加（非唯一） |
| AWMS1 唯一码 U | 绿 + 短音 | 按该码登记的 quantity 累加并勾销；重复扫 → 红 + 长音 + "已收过" |
| AWMS1 批次标签 B | 绿 + 短音 | 带出物料+内部批次；生产退料复用批次 |
| AWMS1 单据码 D | 绿 + 短音 | 使用解析结果中的完整单据与行列表直接打开预建单，不再按 docNo 二次搜索 |
| 外部条码 | 黄 + 提示 | 尽力解析；失败 → 手动录入兜底 |
| 校验失败 | 红 + 长音 | 当场提示修正，不产生脏数据 |

- 扫码框常驻聚焦；扫到即处理。
- 扫描输入基线为 PDA 扫描头/扫描枪的键盘楔入事件；必须保留手工输入和提交入口。摄像头扫码属于 P-20，不在本批。
- 数量输入：大数字键盘 + 步进 ±1；非唯一码**连扫按每标签数量累加**（默认 defaultQtyPerLabel，评审 B-10）。
- 已知信息预填：上次仓库、当前单据上下文。
- 暂存库位：请求必须带 `stagingLocationId`。当前仓只有一个启用 STAGING 时自动带出；有多个时在进入行录入前选择，并始终显示在顶部上下文。
- 扫到 `t=D` 时若单据仓库与当前 PDA 仓库不一致，按 `WAREHOUSE_MISMATCH` 阻断；已作废、已收完等 warning 在进入行录入前展示并阻断。
- 扫到 `t=S` 时把来源批号、生产日期、效期和来源信息保存在当前行；用户手工修改时按契约重新校验。扫到 `t=U` 时不得按默认标签数量 `+1`，必须使用解析结果的 quantity。

## 四、状态矩阵

| 状态 | 表现 |
|---|---|
| 加载 | 顶部进度条；不阻塞扫码 |
| 空态 | 待办为空"无待办"；扫描无匹配"未识别" |
| 错误 | 红底提示条 + 长音；可重试 |
| 无权限 | 入口隐藏 |
| 网络失败 | 提示"请检查网络"并保留当前输入（本期不做离线） |
| 上传中 | 照片位显示进度；上传未完成时禁用最终提交，其他输入保留 |
| 提交中 | 底部主按钮锁定并显示进度；同一 Idempotency-Key 防止重复入账 |
| 提交成功但打印失败 | 保留成功结果，提示可重新预览或到 Web 补打；不得回滚收货 |
| 单据状态失效 | 红底提示并刷新单据；已作废/已收完的单据不可继续录入 |

## 五、交互细节

1. 一屏一任务：成功后自动进入下一步/下一单。
2. 大触控目标（≥48px）、宽间距、单手拇指区、高对比大字。
3. 声音反馈可调音量；成功/失败音色区分。
4. 严格策略：数量≠单据 → 拦截，提示"数量与入库单不一致，需作废重建或联系主管"。
5. 宽松策略：差异提示并记录，不阻断。
6. 拍照：可选 1-3 张，在确认页操作。
7. 打印：结果页提供回执内容/PDF 预览和二维码；Web 可补打。真机打印 P-01 spike 不作为本批门禁。
8. PO 必须来自预建入库单；无单新建请求仅允许 PR/OT，前端隐藏 PO 入口，后端仍需二次校验。
9. 扫预建单后仓库不可改；暂存库位只能选择该仓库下启用的 STAGING。
10. 来源：预建 PO 必须是启用供应商，预建或无单 PR 必须是启用生产车间；OT 可不填来源，填写时必须选择启用来源。批次标签/外标签带出的来源与当前单据或无单上下文不一致时阻断提交。
11. 唯一码行的提交数量必须等于本次唯一码清单 quantity 之和；不一致时就地提示并禁止提交。

## 六、视觉锚点

- PDA 基线：浅色高对比、超大字体、大按钮、声音反馈。
- 状态语义色贯穿：待检 amber / 可用 emerald / 异常 red。
- 顶部始终显示当前上下文（单号/仓库），底部主操作按钮固定。
- 320px~480px 宽度内不得横向滚动；数量、单号和错误提示不得遮挡主操作。
- 结果页以业务结果为主，打印失败作为次级状态展示，不得把成功页改成失败页。
