# 界面规格：首页 Web 工作台（草案 v0.1，D-04）

> 状态：**草案（2026-08-09，讨论中）**。角色：仓管/主管（主要）、作业员（浏览）。回答："现在仓库里有什么待办/异常，最近发生了什么"。

## 二、区块与字段

| 区块 | 内容 | 数据来源（契约依赖） |
|---|---|---|
| KPI 卡 | 待质检 / 待上架 / 异常待办 / 可用SKU | 现有契约可算（待检主体、暂存库位可用行）；异常数需聚合接口 |
| 待办列表 | 待质检单、待上架任务、异常（差异/破损） | 需聚合接口（契约批定义） |
| 快捷操作 | 新建入库单 / 打印中心 / 照片查看 | 页面跳转 |
| 最近库存流水 | 最新 10 条流水 | 现有契约 |
| 今日入库动态 | 今天 收货→质检→上架 时间线 | 流水 + 单据状态聚合 |

## 三、状态矩阵

| 状态 | 表现 |
|---|---|
| 加载 | KPI 骨架、列表骨架；不闪屏 |
| 空态 | KPI 为 0；待办显示"暂无待办，一切正常 ✓"；流水显示空态文案 |
| 错误 | 顶部错误条 + 重试按钮；KPI 区单独失败不拖垮整页 |
| 无权限 | 对应入口/区块隐藏（由注册表权限过滤） |

## 四、交互

1. 仓库选择器：多仓支持，记住上次选择；切换后全部数据重载。
2. 待办卡点击 → 直达对应页面（收货/质检/上架/异常处理）。
3. 刷新：手动刷新 + 进入页面自动刷新；不搞轮询（原型）。
4. KPI 数字用大号等宽数字，状态语义色。

## 五、视觉锚点

- 状态色：待检 amber / 可用 emerald / 冻结 sky / 异常 red。
- KPI 数字大而醒目；待办列表每行"是什么 + 多少 + 去哪"，可扫读。
- 不搞装饰性渐变（作业系统，中性简洁优先）。

## 六、开放问题

1. KPI 选这 4 个够吗？（待质检/待上架/异常待办/可用SKU）
2. "今日入库动态"时间线要不要？（有价值但需聚合接口）
3. 待办列表第一版显示几类？（待质检/待上架/异常 三类够吗）
