# 界面规格：质检 / 上架 PDA（已定稿 v0.3）

> 状态：**已定稿 v0.3（2026-08-21）**。视觉评审与契约双向复核均已通过；本规格为第 4 批前端实现基线。
> 基线：沿用收货 PDA 的一屏一任务、扫码优先、大触控和声音反馈。

## 一、质检流程
```
质检待办列表                    质检确认屏
┌────────────────┐   ┌────────────────┐
│ ← 质检   WH-01   │   │ ← 质检          │
│ RCP-... MAT-001  │   │ MAT-001 螺母 M6  │
│ 批次 260810001   │   │ 批次 260810001   │
│ 200 件  08-10    │   │ 应检 200         │
│ [扫码/选择]      │   │ [PASS 通过]      │
│ 待办：2 单       │   │ [异常：拍照+原因] │
└────────────────┘   └────────────────┘
异常上报屏
┌────────────────┐
│ 异常上报         │
│ 原因：[破损 ▾]   │
│ [拍照 0/3·至少1] │
│ 备注：[______]   │
│ [提交异常]       │
└────────────────┘
```

## 二、质检交互
1. 待办列表：扫码（批次标签 t=B 直接定位行）或点击选择；显示单据号/物料/批次/数量。
2. 确认屏：默认带出整行应检数量；PASS=一键通过（待检→可用）；异常=拍照（1-3 张）+ 原因（破损/数量不符/其他）+ 备注 → 提交 `EXCEPTION`。
3. `EXCEPTION` 提交后从 PDA 待检列表移除，进入主管 Web 待处理列表；同一行不得重复质检。
4. 主管 `PASS` 后转为可用并进入上架待办；主管 `REJECT` 后行保持 `EXCEPTION`、库存保持暂存+待检，禁止上架。退货/报废处置后置。
5. 扫批次标签 `t=B` 后以当前仓库、materialId、batchId 查询待办：恰好 1 条时直接打开；多条时展示候选列表（收货单号、数量、发生时间）让用户选择；0 条时提示“未找到待质检任务”并保留列表。不得静默选择第一条。

## 三、上架流程
```
上架待办 -> 推荐库位屏 -> 标签拆分/预览 -> 扫码确认屏 -> 结果
┌────────────────┐   ┌────────────────┐   ┌────────────────┐
│ ← 上架          │   │ 推荐库位         │   │ 确认上架        │
│ MAT-001 200 件   │   │ DFT-01（理由：   │   │ 库位 DFT-01     │
│ 批次 260810001   │   │  同物料集中）    │   │ 批次 260810001  │
│ 暂存 STG-01      │   │ [改用此库位]     │   │ 数量 200        │
│ [开始]          │   │ [选择其他库位]    │   │ [扫库位码确认]   │
└────────────────┘   └────────────────┘   └────────────────┘
标签拆分/预览屏
┌────────────────┐
│ 每标签数量 [10]   │
│ 将生成 20 张      │
│ [预览标签二维码]  │
│ [继续扫码上架]    │
└────────────────┘
```

## 四、上架交互
1. 待办：行级（receiptLine.status=CHECKED 且未上架）；显示暂存库位。
2. 推荐库位：只返回同仓、启用、`DEFAULT` 库位；优先已有同物料库存的库位，其次按 code 升序。展示推荐理由，可用 ReferencePicker 改选其他合格库位。
3. 本批没有容量模型，不展示“剩余容量”或“已满”，也不承诺满位自动换位；跨仓、停用、`STAGING` 库位必须拦截。
4. 确认：目标库位必须实际扫码，扫到的库位与当前选择不一致时要求确认改选，不允许仅点击完成。
5. 选定目标库位后、扫码上架前完成标签拆分与预览；每标签数量默认 `defaultQtyPerLabel`（可改），N=ceil，尾数如实。真机打印见 P-01；设备不可用时以二维码预览降级，不阻塞后续上架。
6. 上架待办直接返回 `defaultQtyPerLabel`；为空时默认整行 1 张。扫批次标签定位上架待办时同样遵循“1 条直达、多条选择、0 条提示”的规则。

## 五、状态矩阵

| 状态 | 质检 | 上架 |
|---|---|---|
| 加载 | 列表骨架，不抢扫码焦点 | 推荐区域骨架，主按钮禁用 |
| 空态 | “当前仓库无待质检任务” | “当前仓库无待上架任务” |
| 扫码无匹配 | 红条+长音，保留待办列表 | 红条+长音，不改变已选库位 |
| 网络失败 | 保留当前任务、数量、原因和照片，可重试 | 保留推荐和扫码内容，可重试 |
| 上传失败 | 标记失败照片，可删除或重传；禁止提交异常 | 不涉及 |
| 并发失效 | 刷新任务并提示“该任务已被处理” | `VERSION_CONFLICT` 后刷新库存与推荐，不自动重提 |
| 无权限 | 入口隐藏；直接访问显示无权限 | 同左 |
| 成功 | 短音+绿色结果，返回下一待办 | 短音+绿色结果；业务完成不受后续补打影响 |

## 六、视觉锚点

- 320px~480px 宽度内一列布局，触控目标不小于 48px；顶部固定显示仓库、任务号和当前步骤。
- 待检用 amber、可用/成功用 emerald、异常/拦截用 red；不能只靠颜色表达状态，必须配图标和文字。
- PASS 与“上报异常”保持清晰主次，不并排放置两个同等强调的危险操作；`REJECT` 只出现在主管 Web。
- 数量、批次、库位码使用等宽数字；长单号允许换行，不压缩主操作区。
- 扫码框常驻聚焦；键盘楔入扫描为基线，手工输入兜底，摄像头扫码后置。
