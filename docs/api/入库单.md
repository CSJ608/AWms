# 入库单接口契约（草案 v0.2，C-03）

> 状态：**草案 v0.2（2026-08-10）**。v0.2：补充状态机与部分收货说明。
> 依据：通用规范 v1.3、数据模型 v0.3、ADR-003。
> 界面词：入库单（采购入库单/生产入库单/其他入库单）；ty=入库类型。

## 一、生命周期与规则（2026-08-10 确认）

- **创建即 CONFIRMED**（可直接被收货引用），无 DRAFT；不提供行修改（改数量=作废重建）。
- **作废**：CONFIRMED/RECEIVING 可作废，需留痕（谁/何时/原因）；作废后不可再被收货引用。
- **数量一致性策略由类型决定**：PO=STRICT；PR/OT=LENIENT。策略不暴露为可编辑字段。
- 唯一码清单挂在行上（仅 labelType=UNIQUE 允许）；同单内不重复。

## 二、状态机（2026-08-10 确认）

```text
创建 ──► CONFIRMED ──► RECEIVING ──► RECEIVED（终态）
              │            │
              └──► VOIDED ─┘（作废，留痕）
```

| 状态 | 含义 | 进入方式 |
|---|---|---|
| CONFIRMED | 已确认、可被收货引用 | 创建即 CONFIRMED |
| RECEIVING | 已经开始收货 | 首次被 POST /receipts 引用时自动推进 |
| RECEIVED | 全部行收货完成 | 所有行被收货单覆盖后自动推进（终态） |
| VOIDED | 已作废，不可再收货 | 作废接口（仅 CONFIRMED/RECEIVING 可作废，需 reason） |

**部分收货**：
- 一张入库单可被**多张收货单分批引用**（部分到货）。
- 行级：严格（PO）某行 expectedQty 必须一次收齐（quantity==expectedQty，行不可拆分），不同行可分多次；宽松（PR/OT）行可按实收拆分多次，diff 累计记录。
- RECEIVED 判定：所有行都已被收货单覆盖（严格=每行收齐）。

## 五、端点详述

### POST /api/inbound-orders
- 请求：`{ type, warehouseId, sourceType?, sourceCode?, lines: [{ materialId, expectedQty, uniqueCodes? }] }`
- 响应 201：InboundOrder。错误：VALIDATION_ERROR（400）、MATERIAL_NOT_FOUND（404）、WAREHOUSE_NOT_FOUND（404）、ORDER_NUMBER_DUPLICATED（409）、NUMBER_EXHAUSTED（500）、UNAUTHORIZED/FORBIDDEN。
- 规则：type ∈ PO/PR/OT；lines 至少 1 行；expectedQty > 0；uniqueCodes 仅允许物料 labelType=UNIQUE 时提供且同单不重复。

### GET /api/inbound-orders
- 筛选：`type`、`warehouseId`、`status`、`orderNo`（模糊）、`page`、`pageSize`。
- 响应 200：`{items,total,page,pageSize}`。

### GET /api/inbound-orders/{id}
- 响应 200：InboundOrder（含行与唯一码清单）。错误：ORDER_NOT_FOUND（404）。

### POST /api/inbound-orders/{id}/void
- 请求：`{ reason }`（必填）。
- 响应 200：InboundOrder（status=VOIDED）。错误：ORDER_NOT_FOUND（404）、ORDER_STATUS_INVALID（409，RECEIVED/VOIDED 不可作废）。
