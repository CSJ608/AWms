# 打印接口契约（已锁定 v0.4）

> 状态：**已锁定 v0.4（2026-08-21）**。持久化作业、唯一码数量、历史查询、失败重试和文件生命周期经前后端复核无异议。
> 边界：本期内置固定模板（模板配置界面后置）；Web 端后端生成 PDF；PDA 端返回单张打印数据（由 PDA 打印能力实现，后端不驱动打印机）。

## 一、打印类型与端点

| 打印物 | 端点 | 触发端 | 说明 |
|---|---|---|---|
| 单据二维码 D | POST /api/print/inbound-order-qr | Web | 预建单打印（ty/d/wh） |
| 外标签 S | POST /api/print/external-labels | Web | 批量打印（可按预建单行带 ol） |
| 唯一码标签 U | POST /api/print/unique-labels | Web | 批量生成唯一码并登记到行 |
| 批次标签 B（批量） | POST /api/print/batch-labels | Web | 按行拆分 N 张（含尾数） |
| 批次标签 B（单张） | POST /api/print/batch-label-one | PDA | 扫码即打印即贴（姿势 B） |
| 打印作业查询 | POST /api/print/jobs/search | Web | 按业务对象查看历史作业 |
| 打印作业详情 | GET /api/print/jobs/{id} | Web/PDA | 刷新后恢复预览内容 |
| 失败作业重试 | POST /api/print/jobs/{id}/retry | Web/PDA | 复用原 items 重新生成文件 |
| 打印文件 | GET /api/print/jobs/{id}/file | Web | 下载/打印 PDF |

> 收货回执打印：POST /api/receipts/{id}/print（收货契约，返回 PrintJob 同构）。

## 二、DTO

### PrintJob
```json
{
  "id": "uuid",
  "bizType": "RECEIPT_LINE", "bizId": "uuid",
  "templateCode": "BATCH_LABEL",
  "status": "READY",
  "items": [
    { "labelType": "B", "content": "AWMS1:{\"v\":1,\"t\":\"B\",\"s\":\"MAT-001\",\"b\":\"260810001\",\"q\":\"10.0000\"}",
      "readableText": "物料：MAT-001 螺母 M6\n批次：260810001\n数量：10\n库位：DFT-01",
      "quantity": "10.0000" }
  ],
  "fileUrl": "/api/print/jobs/{id}/file",
  "errorCode": null,
  "createdBy": "uuid", "createdByName": "王仓管", "createdAt": "...", "updatedAt": "..."
}
```

- `status`：GENERATING / READY / FAILED。
- Web PDF 作业 READY 时 `fileUrl` 必填；GENERATING/FAILED 时可为 null。PDA 内容预览作业不生成 PDF，READY 时 fileUrl 仍可为 null。
- `items` 持久化到 PrintJobItem，刷新后可按同一 job 恢复预览；`errorCode` 仅 FAILED 有值。
- `bizType/bizId` 可同时为 null；有业务上下文时取 `INBOUND_ORDER / INBOUND_ORDER_LINE / RECEIPT / RECEIPT_LINE`，用于详情页查询历史。两者必须同时为空或同时有值。

## 三、端点详述

### POST /api/print/inbound-order-qr
- 请求：`{ inboundOrderId }`。响应 201：PrintJob（1 张，content 含 ty/d/wh）。
- 错误：ORDER_NOT_FOUND（404）。

### POST /api/print/external-labels
- 请求：`{ items: [{ materialId, count, inboundOrderLineId?, rt?, rc? }] }`，items 1-100 行。
- 每项 `count`：该物料箱数（1-1000，操作员指定）；外标签**不含数量**（q 不入码，标签规范 v0.14）。
- `inboundOrderLineId`：按单打印时传入，必须属于同一 materialId；生成的每张码带 `ol`，PDA 扫到可直接定位行。
- `rt/rc`：可选来源信息，必须成对出现；`rt=S/W` 分别映射 Source 的 `SUPPLIER/WORKSHOP`。按单打印时来源必须与 PO/PR 单据来源一致。
- 响应 201：一个 PrintJob，items 按请求顺序展开。错误：MATERIAL_NOT_FOUND、SOURCE_NOT_FOUND、SOURCE_MISMATCH、ORDER_LINE_MISMATCH、VALIDATION_ERROR。

### POST /api/print/unique-labels
- 请求：`{ inboundOrderLineId, count, qtyPerCode? }`。
- 行为：编号服务批量分配 count 个唯一码（BOX-…，NextN）→ **按每码 quantity 登记到该行 UniqueCode 清单**（UNRECEIVED）→ 打印 count 张（content 含 s+u+q）。
- `qtyPerCode`：默认 1（贵重品一码一件）；>1 需显式传。
- PO 行：`count * qtyPerCode` 加上该行已登记唯一码数量不得超过 expectedQty，超出返回 VALIDATION_ERROR。PR/OT 沿用 LENIENT 策略，允许超出 expectedQty，但 Web 必须显著展示登记总量与应到差异。
- 本端点始终生成新码。补打既有码通过重新打开原 PrintJob/PDF 完成，不再次调用本端点，也不重新登记 UniqueCode。
- 错误：ORDER_NOT_FOUND、ORDER_LINE_MISMATCH、ORDER_STATUS_INVALID（已 VOIDED/RECEIVED 不可）、NUMBER_EXHAUSTED、VALIDATION_ERROR。

### POST /api/print/batch-labels（批量拆分）
- 请求：`{ receiptLineId, qtyPerLabel? }`。
- 行为：N = ceil(actualQty / qtyPerLabel)；前 N-1 张=qtyPerLabel，最后一张=余数（尾数如实打印，标签规范 §7.2）；每张含 s+b+q。
- `qtyPerLabel` 默认：物料 defaultQtyPerLabel；为空则整行 1 张。
- 响应 201：PrintJob（N 张）。错误：RECEIPT_LINE_NOT_FOUND、VALIDATION_ERROR。

### POST /api/print/batch-label-one（PDA 单张，姿势 B）
- 请求：`{ receiptLineId, quantity }`。
- 行为：打印 1 张该箱批次标签（content 含 s+b+quantity）——扫码即打印即贴，PDA 在扫外标签后调用。
- **范围（2026-08-10 裁决）**：接口本期实现；真机驱动（网络热敏/蓝牙）列入 spike 验证（后置项 P-01）；PDA 界面先提供“打印内容预览+二维码”降级，验证通过后再接真机。
- 响应 201：PrintJob（1 张，fileUrl 可空；PDA 端用 items.content 驱动本地打印机）。
- 错误：RECEIPT_LINE_NOT_FOUND、VALIDATION_ERROR。

### GET /api/print/jobs/{id}/file
- 响应 200：PDF 文件流（浏览器打印/下载）。
- 错误：PRINT_JOB_NOT_FOUND（404）；GENERATING 或 PDA 无 PDF 文件时 PRINT_JOB_NOT_READY（409）；FAILED 返回保存的 errorCode/message。

### POST /api/print/jobs/search
- 请求：`{ bizType?, bizId?, templateCode?, status?, page?, pageSize? }`；`bizType/bizId` 作为筛选条件时必须成对出现。
- 响应：`{ items: PrintJob[], total, page, pageSize }`，默认 `createdAt desc, id desc`。列表可省略大字段 `items[].content/readableText`，打开详情后获取完整内容。

### GET /api/print/jobs/{id}
- 响应 200：完整 PrintJob（含 items），用于刷新恢复预览和既有唯一码标签补打。
- 错误：PRINT_JOB_NOT_FOUND（404）。

### POST /api/print/jobs/{id}/retry
- 仅 FAILED 作业可重试，要求 `Idempotency-Key`。服务端以状态条件更新为 GENERATING，复用原 PrintJobItem 重新生成预览/PDF，成功转 READY，失败仍为 FAILED 并更新 errorCode。
- 不创建新的标签内容，不重新分配编号，不新增或修改 UniqueCode；返回同一个 PrintJob id。
- 错误：PRINT_JOB_NOT_FOUND、PRINT_JOB_STATUS_INVALID（当前不是 FAILED 或已有重试在执行）。

## 四、业务规则

1. **持久化与留痕**：每次新生成请求都创建 PrintJob 和按序 PrintJobItem；PrintJob 同时承担生成作业与打印/预览留痕，不另建语义重叠的 PrintLog。
2. **内置模板**：收货回执 / 单据二维码 / 外标签 / 唯一码标签 / 批次标签 五种固定模板；模板配置界面后置。
3. **唯一码生成**：编号服务 NextN、UniqueCode 登记、PrintJob 和 PrintJobItem 在同一事务提交，避免有码无作业或有作业无码；PDF/预览文件随后生成，失败保留可重试的 FAILED 作业。
4. **拆分与尾数**：固定每标签数量 + 尾数模式（标签规范 §7）；"手动每张不均匀"后置。
5. **贴标签姿势**：默认 B（批次标签贴箱，扫码即打印即贴）；可配置免贴（单批次独占库位，待现场验证）。Web 入库单详情按单行触发打印参数对话框，本批不提供多行勾选或跨行批量打印。
6. 权限：按操作权限控制（打印/作废等）。
7. **验收基线**：Web 打印端点必须生成可下载/浏览器打印的 PDF；PDA 端必须能展示 `items.content` 的二维码和可读文字。真机打印为 P-01 spike，不阻塞本批验收。
8. **失败隔离**：打印在业务提交成功后独立触发；打印失败不得回滚收货、质检或上架结果。FAILED 使用 retry 复用原作业；READY 补打复用原 PDF。用户明确要求重新生成内容时才创建新 PrintJob；唯一码补打不得重新调用 unique-labels。
9. **文件生命周期**：Web PDF 先写临时文件，成功原子移动到正式路径后作业才进入 READY；FAILED 保存稳定 errorCode，不暴露物理路径。文件删除策略后置，本批保留全部生成记录。
10. **幂等**：所有生成类 POST 与 retry 均要求 `Idempotency-Key`（`/print/jobs/search` 除外）；重复请求返回首次 PrintJob，尤其不得因双击重复登记唯一码。
