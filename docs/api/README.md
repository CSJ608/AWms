## 二、通用规范

### 2.1 响应格式（统一 envelope + HTTP 状态码，混合方案）

成功（2xx）：`{ "code": "OK", "message": "ok", "data": { } }`
业务错误（4xx/5xx）：`{ "code": "MATERIAL_CODE_DUPLICATED", "message": "物料编码 MAT-001 已存在", "data": null }`

- **状态码表达成败类别，code 表达精确业务原因**（基础设施/工具无需解析 body；纯 200 使监控/网关失效，纯状态码粒度不够）。
- HTTP 语义：200 成功；400 参数/校验；401 未鉴权；403 无权限；404 不存在；409 冲突；422 业务校验；500 内部错误。

### 2.2 分页（已确认）

- 列表统一：`{ items, total, page, pageSize }`；`pageSize=0` 全量；筛选空值不发送。

### 2.3 时间与数量（已确认）

- 时间 ISO 8601 UTC；日期 yyyy-MM-dd；**数量 JSON 字符串**（decimal 18,4，示例 "200.0000"）；ID UUID。

### 2.4 鉴权（已确认）

- `Authorization: Bearer <token>`；`Accept-Language: zh|en`；401 静默刷新重放，失败跳登录；403 提示。

### 2.5 i18n（已确认）

- 错误文案归后端（messages.zh.json/en.json，含参数，未知语言回退中文，message 必须完整）；前端只维护 UI 文案；两端不共享 i18n 文件（本期）。

### 2.6 幂等（已确认）

- 写操作 `Idempotency-Key: <uuid>`；重复返回首次结果；适用收货/质检/上架等。

### 2.7 前端错误处理（已定稿）

- 默认直接展示后端 message；不维护错误文案映射。
- **code = 前端判断"是否需要做特别的事"的钥匙**：需要静默 → 静默执行；需要提示 → 界面提示；由前端按 code + 上下文决定。
- 行为分支：UNAUTHORIZED（静默刷新重放）/ FORBIDDEN / QTY_MISMATCH_STRICT（引导作废重建）/ IMPORT_VALIDATION_FAILED（展示明细）/ UNIQUE_CODE_ALREADY_RECEIVED（静默刷新清单+防重）/ ORDER_VOIDED、VERSION_CONFLICT（静默刷新+提示重操作）/ NETWORK_ERROR、UNKNOWN_ERROR（本地兜底）。

### 2.8 错误码形式（已确认）

- 契约层：字符串 code（模块前缀）；内部编号 hex 区间预占（0x00~0x05）；前端只消费字符串 code。

### 2.9 编号规范（编号服务，2026-08-10 确认）

- **需要编号的对象**：入库单号、收货单号、内部批次号、事务组号、唯一码（标签）、导入任务号、打印任务号；后续出库单/盘点单/调拨单。
- **格式**：`{前缀}{yyyyMMdd}-{序号}`，序号按"类型+日期"重置、补零（默认 4 位，可配置）。
  示例：`PO-20260810-0001`、`RCP-20260810-0001`、`B-20260810-0001`、`TXN-20260810-0001`、`BOX-20260810-0001`。
- **实现**：平台化 NumberingService——规则注册（type → 前缀/位数/是否按日重置）+ 序号表（Sequence），原子自增（UPDATE ... RETURNING，行锁保证并发唯一）。
- **生成时机**：与业务提交**同一事务**；回滚产生的**跳号允许**（保证唯一与单调，不追求连续）。
- 约束：对外编号全局唯一；UUID 仅作内部主键；前端不生成编号。
