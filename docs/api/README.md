## 二、通用规范

### 2.1 响应格式（统一 envelope + HTTP 状态码，混合方案）

成功（2xx）：`{ "code": "OK", "message": "ok", "data": { } }`
业务错误（4xx/5xx）：`{ "code": "MATERIAL_CODE_DUPLICATED", "message": "物料编码 MAT-001 已存在", "data": null }`

- **状态码表达成败类别，code 表达精确业务原因**（2026-08-10 定：让基础设施/工具无需解析 body；纯 200 使监控/网关失效，纯状态码粒度不够）。
- HTTP 语义：200 成功；400 参数/校验；401 未鉴权；403 无权限；404 不存在；409 冲突；422 业务校验；500 内部错误。

### 2.2 分页（已确认）

- 列表统一：`{ items, total, page, pageSize }`；`pageSize=0` 全量；筛选空值不发送。

### 2.3 时间与数量（已确认）

- 时间 ISO 8601 UTC；日期 yyyy-MM-dd；**数量 JSON 字符串**（decimal 18,4，示例 "200.0000"）；ID UUID。

### 2.4 鉴权（已确认）

- `Authorization: Bearer <token>`；`Accept-Language: zh|en`；401 静默刷新重放，失败跳登录；403 提示。

### 2.5 i18n（已确认）

- 错误文案归后端（messages.zh.json/en.json，含参数，未知语言回退中文，message 必须完整）；前端只维护 UI 文案；两端不共享 i18n 文件（本期）。

### 2.6 幂等（已确认）

- 写操作 `Idempotency-Key: <uuid>`；重复返回首次结果；适用收货/质检/上架等。

### 2.7 前端错误处理（已定稿）

- 默认直接展示后端 message；不维护错误文案映射。
- **code = 前端判断"是否需要做特别的事"的钥匙**：需要静默 → 静默执行（刷新 token 重放、刷新列表/单据）；需要提示 → 界面提示；两者都由前端按 code + 当前上下文决定。
- 行为分支：UNAUTHORIZED（静默刷新重放）/ FORBIDDEN（提示）/ QTY_MISMATCH_STRICT（引导作废重建）/ IMPORT_VALIDATION_FAILED（展示明细）/ UNIQUE_CODE_ALREADY_RECEIVED（静默刷新清单+防重提示）/ ORDER_VOIDED、VERSION_CONFLICT（静默刷新+提示重操作）/ NETWORK_ERROR、UNKNOWN_ERROR（本地兜底）。

### 2.8 错误码形式（已确认）

- 契约层：字符串 code（模块前缀，大写蛇形）；内部编号 hex 区间预占（0x00 通用 / 0x01 主数据 / 0x02 入库链 / 0x03 库存 / 0x04 系统 / 0x05 支撑）；前端只消费字符串 code。
