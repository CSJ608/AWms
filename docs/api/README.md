## 二、通用规范

### 2.1 响应格式（统一 envelope + HTTP 状态码，混合方案）

成功（2xx）：

```json
{ "code": "OK", "message": "ok", "data": { } }
```

业务错误（4xx / 5xx）：

```json
{ "code": "MATERIAL_CODE_DUPLICATED", "message": "物料编码 MAT-001 已存在", "data": null }
```

**为什么用 HTTP 状态码（混合方案，2026-08-10 讨论定）**：

- 状态码表达"请求成败的类别"，body.code 表达"精确业务原因"。
- 状态码让基础设施与工具（网关/监控告警/DevTools/OpenAPI 客户端）**无需解析 body** 就能理解成败；纯 200+业务码会使 5xx 告警、网关/CDN 行为、工具链全部失效。
- 纯状态码粒度太粗（无法表达"严格数量不一致/唯一码重复"），仍需 code 补充。
- 结论：**混合**。HTTP 语义：200 成功；400 参数/校验；401 未鉴权；403 无权限；404 不存在；409 冲突；422 业务校验；500 内部错误。

### 2.2 分页（已确认）

- 所有列表接口统一：`{ "items": [...], "total": 0, "page": 1, "pageSize": 20 }`。
- 请求参数：`page`（≥1）、`pageSize`（1..200；`pageSize=0` 全量）。
- 筛选参数：空值不发送；各模块契约声明筛选字段。

### 2.3 时间与数量

- 时间：ISO 8601 UTC（`yyyy-MM-dd'T'HH:mm:ss'Z'`），前端本地化展示。
- 日期：`yyyy-MM-dd`。
- **数量：JSON 一律用字符串**（decimal(18,4)，避免 IEEE754 精度丢失）：

```json
{ "quantity": "200.0000" }
{ "quantity": "123456789012.3456" }
```

  - 后端解析为 decimal，计算只在后端；前端 `formatQuantity` 去尾零展示（"200.0000" → "200"），输入框按字符串提交。
- ID：UUID 字符串。

### 2.4 鉴权（已确认）

- 登录：`POST /api/auth/login` 返回 `token` + 用户信息 + 权限/菜单。
- 请求头：`Authorization: Bearer <token>`；`Accept-Language: zh|en`。
- 401 → 前端静默刷新 token 并重放；刷新失败 → 跳登录；403 → 提示无权限。

### 2.5 i18n（已确认 2026-08-10）

- **错误文案归后端**：后端维护 `messages.zh.json` / `messages.en.json`（含动态参数），按 Accept-Language 返回；未知语言回退中文；message 必须完整。
- **前端只维护 UI 文案，不维护错误码文案映射**。
- **两端不共享 i18n 文件**（本期）：跨技术栈同步成本高、发布耦合；未来要统一再评估。

### 2.6 幂等（已确认）

- 写操作支持 `Idempotency-Key: <uuid>`；后端记录 key+结果，重复返回首次结果。
- 适用：收货提交、质检、上架等关键写操作。

### 2.7 前端错误处理（已确认 2026-08-10）

- **默认直接展示后端 `message`**；不维护错误文案映射。
- **code 仅用于行为分支**（2026-08-10 讨论定，含"静默调用别的接口"场景）：

| code | 前端行为 |
|---|---|
| UNAUTHORIZED（401） | **静默刷新 token → 重放原请求**；刷新失败才跳登录 |
| FORBIDDEN（403） | 提示无权限 |
| QTY_MISMATCH_STRICT | 引导"作废重建"入口 |
| IMPORT_VALIDATION_FAILED | 自动展示 data 失败明细 |
| UNIQUE_CODE_ALREADY_RECEIVED | 静默刷新待收唯一码清单 + 防重提示 |
| ORDER_VOIDED / VERSION_CONFLICT | 静默刷新当前列表/单据，提示重新操作 |
| NETWORK_ERROR / UNKNOWN_ERROR | 前端本地兜底文案 |

### 2.8 错误码形式（已确认 2026-08-10）

- **契约层：字符串 code**（大写蛇形，模块前缀，如 MATERIAL_CODE_DUPLICATED）——前端行为分支可读、IDE 友好。
- **内部编号：hex 区间预占**（通用 0x00xxx / 主数据 0x01xxx / 入库链 0x02xxx / 库存 0x03xxx / 系统 0x04xxx / 支撑 0x05xxx）——用于日志/工单/对接。
- 前端只消费字符串 code；hex 不进前端代码。
