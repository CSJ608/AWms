## 二、通用规范

### 2.1 响应格式（统一 envelope）

成功（2xx）：

```json
{ "code": "OK", "message": "ok", "data": { } }
```

业务错误（4xx / 5xx）：

```json
{ "code": "MATERIAL_CODE_DUPLICATED", "message": "物料编码 MAT-001 已存在", "data": null }
```

- HTTP 语义：200 成功；400 参数/校验；401 未鉴权；403 无权限；404 不存在；409 冲突；422 业务校验；500 内部错误。
- `code`：稳定业务码（大写蛇形），**用于前端行为分支与日志/监控**。
- `message`：**完整本地化文案（含动态参数）**，按 Accept-Language 返回，**前端默认直接展示**。
- `data`：可带结构化错误详情（如导入失败明细、字段校验错误列表）。

### 2.2 分页

- 所有列表接口统一：`{ "items": [...], "total": 0, "page": 1, "pageSize": 20 }`。
- 请求参数：`page`（≥1）、`pageSize`（1..200；`pageSize=0` 表示全量）。
- 筛选参数：空值不发送；各模块契约声明筛选字段。

### 2.3 时间与数量

- 时间：ISO 8601 UTC（`yyyy-MM-dd'T'HH:mm:ss'Z'`），前端本地化展示。
- 日期：`yyyy-MM-dd`。
- **数量：JSON 一律用字符串**（decimal(18,4)），前端 formatQuantity 展示。
- ID：UUID 字符串。

### 2.4 鉴权

- 登录：`POST /api/auth/login` 返回 `token` + 用户信息 + 权限/菜单。
- 请求头：`Authorization: Bearer <token>`；`Accept-Language: zh|en`。
- 401 → 前端清除会话跳登录；403 → 提示无权限。

### 2.5 i18n（2026-08-10 讨论修订）

- **错误文案归后端**：后端维护 `messages.zh.json` / `messages.en.json`（含动态参数），按 Accept-Language 返回；未知语言回退中文；`message` 必须完整（不得只返回 code）。
- **前端只维护 UI 文案**（按钮/菜单/提示/表格头），**不维护错误码文案映射**。
- **两端不共享 i18n 文件**（本期）：跨技术栈同步成本高、发布耦合；未来若需统一文案源再评估独立文案仓库。

### 2.6 幂等（防重复提交）

- 写操作支持 `Idempotency-Key: <uuid>` 请求头；后端记录 key+结果，重复返回首次结果。
- 适用：收货提交、质检、上架等关键写操作。

### 2.7 前端错误处理约定（2026-08-10 讨论修订）

- **默认直接展示后端 `message`**。
- **code 仅用于行为分支**（前端保留少量本地兜底文案）：
  - `NETWORK_ERROR`（前端本地）：网络失败/超时；
  - `UNKNOWN_ERROR`（前端本地）：未知 code 或 message 为空时的兜底；
  - `UNAUTHORIZED`：清除会话跳登录；
  - `FORBIDDEN`：提示无权限；
  - `QTY_MISMATCH_STRICT`：严格拦截，可引导"作废重建"；
  - `IMPORT_VALIDATION_FAILED`：展示 `data` 失败明细；
  - `UNIQUE_CODE_ALREADY_RECEIVED`：防重特殊提示。
- 其余错误码：前端不感知，直接展示 message。
