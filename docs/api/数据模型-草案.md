# 数据模型（已锁定 v0.6）

> 状态：**已锁定 v0.6（2026-08-21）**。数量守恒、打印作业、数据库防重与并发验收要求经前后端复核无异议。
> 依据：概念设计 v1.0、通用规范 v2.1、标签规范 v0.14。

## 一、建模原则
1. 概念命名保持；表名与契约字段英文；界面词用《术语对照表》。
2. 只建本期功能需要的表；预留概念只留字段位。
3. 流水只追加；物理库存带版本号防并发。
4. 来源单据与收货单分离（逻辑引用，ADR-003）。

## 二、实体清单（分组）
- 系统基础：User / Role / Permission / Module / MenuEntry / UserRole / RolePermission
- 主数据：Material / Warehouse / Location / Source / Batch（系统自动建立）
- 入库链：InboundOrder / InboundOrderLine / UniqueCode / Receipt / ReceiptLine / QualityCheck / PutawayRecord
- 库存账目：StockSubject / PhysicalInventory / StockLedger / TxnGroup
- 支撑：Attachment / PrintJob / PrintJobItem / ImportTask / ImportTaskDetail / Sequence / IdempotencyRecord

## 四、关键规则
1. 唯一性：material.code、warehouse.code、location(warehouseId,code)、batch(materialId,batchNo)、order.orderNo、receipt.receiptNo、subject(warehouse,material,batch,status)、physical(location,subject)、sequence(type,scopeKey,bizDate)。
2. **收货行匹配优先 orderLineId**（扫标签 ol 提供）；仅按 materialId 匹配在"同物料多行"时歧义，需带 ol 或由前端选行。
3. 非批控物料用默认空批次（batchNo=DEFAULT）。
4. 流水只追加；物理库存带 version；收货/质检/上架同一事务。
5. 编号统一走 NumberingService（Sequence 表）。
6. Receipt.stagingLocationId 必须与 warehouseId 同仓且为 ENABLED/STAGING；PutawayRecord.toLocationId 必须同仓且为 ENABLED/DEFAULT。
7. QualityCheck REJECT 不产生库存流水；行保持 EXCEPTION。PASS 的状态转换、上架的库位转换各自在独立事务内保持库存与流水一致。
8. 附件归属：收货照片 `RECEIPT/receiptId`；质检异常照片 `EXCEPTION/qualityCheckId`。本批 PASS 不接收照片，不使用 `QUALITY_CHECK` 附件类型。
9. PrintJob/PrintJobItem 是可恢复的持久化生成记录；Web PDF 的 filePath 必须在 READY 前落盘，PDA 作业 filePath 可空。
10. 收货、质检、异常处理和上架不得只依赖“先查后写”或全局过滤器防重；业务状态、库存、流水与幂等完成记录必须在同一事务中提交，或由等价业务唯一键保证重放不会重复入账。

## 五、唯一约束与索引（第 4 批）

### 5.1 唯一约束

| 实体 | 唯一约束 | 目的 |
|---|---|---|
| InboundOrderLine | `(orderId, lineNo)` | 单据内行号唯一 |
| UniqueCode | `code` | 唯一码全局唯一 |
| ReceiptLine | `(receiptId, lineNo)` | 收货单内行号唯一 |
| QualityCheck | `receiptLineId` | 本批整行全检且只允许一次提交，异常通过 resolve 处理 |
| PutawayRecord | `receiptLineId` | 本批整行只允许上架一次 |
| StockSubject | `(warehouseId, materialId, batchId, status)` | 库存主体唯一 |
| PhysicalInventory | `(locationId, subjectId)` | 库位库存唯一 |
| StockLedger | `(txnGroupId, seq)` | 复式流水组内顺序唯一 |
| PrintJobItem | `(printJobId, seq)` | 打印项顺序唯一 |
| IdempotencyRecord | `key` | 同一幂等键只保留一条首次结果 |

### 5.2 查询索引

- InboundOrder：`(warehouseId,status,createdAt desc)`、`(sourceType,sourceCode)`。
- Receipt：`(warehouseId,status,occurredAt desc)`、`inboundOrderId`。
- ReceiptLine：`orderLineId`、`(materialId,batchId,status)`。
- QualityCheck：`(resolutionAction,checkedAt desc)`。
- PutawayRecord：`toLocationId`、`putawayAt desc`。
- StockLedger：`subjectId`、`locationId`、`occurredAt desc`。
- Attachment：`(bizType,bizId)`；PrintJob：`(bizType,bizId,createdAt desc)`。

### 5.3 并发验收

- 不同 Idempotency-Key 并发提交同一收货行、质检行或上架行时，最多一个成功。
- 失败请求不得留下批次、库存、流水、唯一码状态或已关联附件的部分写入。
- 同一 Idempotency-Key 重放返回首次结果；业务成功后即使响应写回失败，也不得在 TTL 后重复入账。
