# 收货接口契约（草案 v0.1，C-03）

> 状态：**草案 v0.1（2026-08-10）**。依据：通用规范 v1.3、数据模型 v0.3、收货链工作流 v0.3.2、标签规范 v0.5、ADR-003。
> 界面词：收货单/收货回执；待办（待质检/待上架）；状态（待检/可用）。

## 一、流程与规则（2026-08-10 确认）

1. **收货提交**：支持无预建单（手动/扫料）与有预建单（扫单）两种上下文；同一套入账逻辑。
2. **一致性策略**：PO=STRICT（逐行 实收==应到，否则 QTY_MISMATCH_STRICT）；PR/OT=LENIENT（按实收，记录 diff，允许超收）。
3. **批控物料必须批次**：扫描 t=B 复用原批次（生产退料）；t=S 带 rb/pd 生成新批次；否则 BATCH_REQUIRED。
4. **唯一码**：预建单行有清单时，扫一个勾一个；不在清单 UNIQUE_CODE_NOT_IN_ORDER；重复 UNIQUE_CODE_ALREADY_RECEIVED。
5. **拍照**：附件先上传拿 uploadId（附件契约），收货提交时带 photos。
6. **提交幂等**：Idempotency-Key。
7. **入账**：同一事务内——创建内部批次（如需要）→ 库存主体（待检）→ 物理库存（staging）→ 流水（外部操作）。

## 二、端点

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/receipts | 提交收货（幂等） |
| GET | /api/receipts | 收货单列表（分页+筛选） |
| GET | /api/receipts/{id} | 收货单详情 |
| POST | /api/receipts/{id}/print | 打印收货回执（返回打印数据，打印契约细化） |
| GET | /api/quality-todos | 质检待办（行级） |
| POST | /api/receipt-lines/{lineId}/quality-check | 质检确认（PASS/EXCEPTION） |
| POST | /api/quality-checks/{checkId}/resolve | 主管处理 EXCEPTION |
| GET | /api/putaway-todos | 上架待办（行级） |
| GET | /api/putaway-todos/{receiptLineId}/recommendations | 推荐库位（附理由） |
| POST | /api/putaway-records | 上架提交 |

## 四、端点详述

### POST /api/receipts（核心）
- 请求（有预建单）：`{ warehouseId, inboundOrderId, lines: [{ materialId, quantity, uniqueCodes? }], photos? }`
- 请求（无预建单）：`{ warehouseId, sourceDocType?, sourceDocNo?, lines: [{ materialId, batchId?, batchProps?, quantity }], photos? }`
  - `batchId`：扫描 t=B 复用原批次时传（生产退料）。
  - `batchProps`：`{ sourceBatchNo?, sourceType?, sourceCode?, productionDate?, expiryDate? }`（t=S 留档/手动录入）。
- 响应 201：Receipt。错误：VALIDATION_ERROR、ORDER_NOT_FOUND、ORDER_VOIDED、ORDER_STATUS_INVALID、ORDER_LINE_MISMATCH、QTY_MISMATCH_STRICT、UNIQUE_CODE_NOT_IN_ORDER、UNIQUE_CODE_ALREADY_RECEIVED、BATCH_REQUIRED、MATERIAL_NOT_FOUND、WAREHOUSE_NOT_FOUND、NUMBER_EXHAUSTED、UNAUTHORIZED/FORBIDDEN。

### GET /api/receipts
- 筛选：`status`、`warehouseId`、`receiptNo`、`dateFrom`、`dateTo`、`page`、`pageSize`。

### GET /api/receipts/{id}
- 响应 200：Receipt。错误：RECEIPT_NOT_FOUND（404）。

### GET /api/quality-todos
- 参数：`warehouseId`、`page`、`pageSize`。
- 响应：行级待检列表（receiptLine.status=RECEIVED）：`{ receiptLineId, receiptNo, materialCode, materialName, batchNo, quantity, receivedAt }`。

### POST /api/receipt-lines/{lineId}/quality-check
- 请求：`{ result, checkedQty, exceptionReason?, photoIds? }`。
- PASS：行状态→CHECKED；库存主体 待检→可用（状态变更流水，组内求和=0）。
- EXCEPTION：行状态→EXCEPTION；记录质检单，待主管 resolve。
- 错误：RECEIPT_STATUS_INVALID、QC_STATUS_INVALID（409）、RECEIPT_LINE_NOT_FOUND（404，需补入枚举）。

### POST /api/quality-checks/{checkId}/resolve
- 请求：`{ action(PASS/REJECT), note? }`。
- PASS：同质检通过（主体→可用）。
- REJECT：记录备注，主体保持待检（本期不做退供/冻结，后续批）。
- 错误：QUALITY_CHECK_NOT_FOUND（404）。

### GET /api/putaway-todos
- 参数：`warehouseId`、`page`、`pageSize`。
- 响应：行级待上架（receiptLine.status=CHECKED 且未上架）：`{ receiptLineId, receiptNo, materialCode, materialName, batchNo, quantity, stagingLocationCode }`。

### GET /api/putaway-todos/{receiptLineId}/recommendations
- 响应：LocationRecommendation[]（同物料集中 > 空库位按编码序，理由后端生成）。
- 错误：RECEIPT_LINE_NOT_FOUND（404）。

### POST /api/putaway-records
- 请求：`{ receiptLineId, toLocationId, quantity, recommendedLocationId? }`。
- 规则：行状态=CHECKED；目标库位 type=DEFAULT；同一事务 物理库存 staging→目标 + 流水。
- 响应 201：PutawayRecord。错误：RECEIPT_LINE_NOT_FOUND、PUTAWAY_LOCATION_INVALID（400）、RECEIPT_STATUS_INVALID、INSUFFICIENT_STOCK（409）、VERSION_CONFLICT（409）。
