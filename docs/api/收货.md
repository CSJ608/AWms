# 收货接口契约（已锁定 v0.5）

> 状态：**已锁定 v0.5（2026-08-21）**。双向开工评审意见和用户裁决已回写，前后端基于 `84c5c8a` 复核无异议。
> 依据：通用规范 v2.1、数据模型 v0.6、标签规范 v0.14、ADR-003。

## 一、流程与规则
1. 收货提交支持无预建单与有预建单两种上下文；**PO 必须引用预建入库单，无单新建只允许 PR/OT**。
2. 一致性策略：PO=STRICT（逐行 实收==应到，行不可拆分；同单不同行可分次收货）；PR/OT=LENIENT（按实收、diff 累计、允许超收）。
3. 行匹配（有预建单）：优先 orderLineId（扫外标签 ol 直接定位）；无 ol 按 materialId（同物料多行歧义 → 400）。
4. 批控必须批次：有单/无单行均可传 `batchId? / batchProps?`，两者互斥。`batchId` 仅用于 PR 生产退料复用内部批次；`batchProps` 来自 t=S/外部条码/手工录入并生成新内部批次；否则 BATCH_REQUIRED。
5. 唯一码：清单勾销；每个码保存代表数量。唯一码物料的行 `quantity` 必须等于本次 `uniqueCodes` 已登记数量之和；不一致 `UNIQUE_CODE_QTY_MISMATCH`，不在单 `UNIQUE_CODE_NOT_IN_ORDER`，重复 `UNIQUE_CODE_ALREADY_RECEIVED`。
6. 拍照：附件先上传拿 uploadId，提交带 photos；收货照片 0-3 张，质检异常照片 1-3 张。
7. 幂等：Idempotency-Key（通用规范 2.6，IdempotencyRecord 表实现）。
8. 入账：同一事务——内部批次 → 待检主体 → staging 物理库存 → 流水（外部操作）。收货请求必须确定 `stagingLocationId`；同仓只有一个启用 STAGING 时前端可自动带出，多个时必须选择。
9. 质检 `REJECT`：QualityCheck 记录为已处理，但 ReceiptLine 保持 EXCEPTION，库存留在 staging 且保持 PENDING_INSPECTION，禁止进入上架待办。
10. 推荐库位：同仓、ENABLED、DEFAULT；优先已有同物料库存，再按 code asc。本批无容量字段，不做满位判断。

## 二、Receipt 状态流转（2026-08-10 显式化）
```
创建 ──► RECEIVING ──► CHECKING ──► PUTAWAY ──► DONE
```
| 状态 | 进入条件 |
|---|---|
| RECEIVING | 收货提交创建 |
| CHECKING | 首次质检提交（任一收货行执行 quality-check） |
| PUTAWAY | 全部收货行均已通过质检（CHECKED/PUTAWAY_DONE），且无 EXCEPTION |
| DONE | 全部收货行 PUTAWAY_DONE，且无未 resolve 的 EXCEPTION |

- 行状态：RECEIVED → CHECKED（质检 PASS）→ PUTAWAY_DONE（上架完成）；EXCEPTION 分支待 resolve。
- 入库单 RECEIVED 推进：见入库单契约 v0.5（同事务方案 A）。

### 4.4 字段可空性

| DTO 字段 | 必填/可空 | 场景规则 |
|---|---|---|
| `Receipt.inboundOrderId` | 可为 null | 预建单收货必填；无单 PR/OT 为 null |
| `sourceDocType` | 必填 | PO/PR/OT；无单 PO 被拒绝 |
| `sourceDocNo` | 可为 null | 预建单取 orderNo；无单 PR/OT 可手填或为空 |
| `sourceType/sourceCode` | 条件必填，可同时为 null | PO=SUPPLIER 必填；PR=WORKSHOP 必填；OT 可空；必须成对 |
| `ReceiptLine.orderLineId/orderLineNo/expectedQty` | 可为 null | 预建单收货必填；无单 PR/OT 为 null |
| `ReceiptLine.qtyDiff` | 可为 null | 有预建单为 actualQty-expectedQty；无单 PR/OT 为 null |
| `sourceBatchNo/productionDate/expiryDate` | 可为 null | 按批次属性留档 |
| `PutawayTodo.defaultQtyPerLabel` | 可为 null | 来自物料；为空时前端默认整行 1 张 |

## 五、端点详述
### POST /api/receipts（核心）
- 有预建单：`{ warehouseId, stagingLocationId, inboundOrderId, lines: [{ orderLineId?, materialId, batchId?, batchProps?, quantity, uniqueCodes? }], photos? }`。
- 无预建单：`{ warehouseId, stagingLocationId, sourceDocType, sourceDocNo?, sourceType?, sourceCode?, lines: [{ materialId, batchId?, batchProps?, quantity }], photos? }`；`sourceDocType` 仅允许 PR/OT。
- `batchProps`：`{ sourceBatchNo?, productionDate?, expiryDate?, sourceType?, sourceCode? }`；日期为 yyyy-MM-dd，sourceType/sourceCode 必须成对且引用启用的 Source。
- `batchId` 与 `batchProps` 互斥。`batchId` 只接受 PR 生产退料且必须属于当前 materialId；其他场景传 batchId 返回 VALIDATION_ERROR。
- `batchProps` 来源为空时继承单据/收货来源；显式提供时必须引用启用的 Source。当前单据或无单收货头已指定来源时必须一致，否则 `SOURCE_MISMATCH`；无来源的 OT 允许各行保存不同的有效批次来源。
- 无单 PR：`sourceType=WORKSHOP` 且来源有效；无单 OT：来源可空，填写时必须有效；无单 PO 返回 `ORDER_REQUIRED_FOR_PO`。
- 唯一码物料必须传 `uniqueCodes: string[]`。服务端按登记清单求和；请求 `quantity` 必须与本次唯一码数量之和相等。非唯一码物料不得传 uniqueCodes。
- 响应 201：Receipt。错误：VALIDATION_ERROR、ORDER_NOT_FOUND、ORDER_VOIDED、ORDER_STATUS_INVALID、ORDER_LINE_MISMATCH、ORDER_REQUIRED_FOR_PO、QTY_MISMATCH_STRICT、UNIQUE_CODE_NOT_IN_ORDER、UNIQUE_CODE_ALREADY_RECEIVED、UNIQUE_CODE_QTY_MISMATCH、BATCH_REQUIRED、SOURCE_NOT_FOUND、SOURCE_MISMATCH、STAGING_LOCATION_INVALID、MATERIAL_NOT_FOUND、WAREHOUSE_NOT_FOUND、NUMBER_EXHAUSTED、UNAUTHORIZED/FORBIDDEN。
- `stagingLocationId` 必须属于 `warehouseId`、ENABLED 且 type=STAGING；否则 `STAGING_LOCATION_INVALID`。
- 无预建单传 PO → `ORDER_REQUIRED_FOR_PO`；失败不得创建批次、库存或流水。

### POST /api/receipts/search
- 请求：`{ status?, warehouseId?, receiptNo?, dateFrom?, dateTo?, filter?, sort?, page?, pageSize? }`。
- 支持 filter DSL；**字段白名单**：receiptNo、warehouseId、inboundOrderId、sourceDocType、sourceDocNo、status、operatorId、occurredAt。
- **排序白名单**：receiptNo、status、occurredAt；默认 occurredAt desc。
### GET /api/receipts/{id}
- 响应 200：Receipt。错误：RECEIPT_NOT_FOUND（404）。
### POST /api/quality-todos/search
- 请求：`{ warehouseId?, materialId?, batchId?, keyword?, page?, pageSize? }`；keyword 匹配 receiptNo/materialCode/materialName/batchNo。
- 响应：`{ items: QualityTodo[], total, page, pageSize }`；只返回 receiptLine.status=RECEIVED，默认 receivedAt desc。
- 扫 t=B 后以前端当前仓库 + materialId + batchId 查询：1 个候选直接进入，多个候选展示列表选择，0 个显示无匹配；不得任意取第一条。
### POST /api/receipt-lines/{lineId}/quality-check
- 请求：`{ result, checkedQty, exceptionReason?, note?, photoIds? }`，要求 Idempotency-Key。
- 本期全检：checkedQty 必须等于行 actualQty。PASS 不要求照片；EXCEPTION 必须 exceptionReason 且 photoIds 1-3 张。
- PASS：行→CHECKED；同一事务内 staging 上待检主体 `-quantity`、可用主体 `+quantity`，写同组两条流水。
- EXCEPTION：行→EXCEPTION，不改变库存主体和流水，等待主管处理。
- EXCEPTION 的 `photoIds` 关联为 `bizType=EXCEPTION, bizId=qualityCheck.id`；本批 PASS 不接收照片。收货照片关联为 `bizType=RECEIPT, bizId=receipt.id`。
- 错误：RECEIPT_LINE_NOT_FOUND、QC_STATUS_INVALID、RECEIPT_STATUS_INVALID、VALIDATION_ERROR。

### POST /api/quality-checks/search
- 请求：`{ warehouseId?, resolutionStatus?(PENDING/RESOLVED), exceptionReason?, keyword?, page?, pageSize? }`。
- 响应：`{ items: QualityExceptionItem[], total, page, pageSize }`；默认 checkedAt desc。
### POST /api/quality-checks/{checkId}/resolve
- 请求：`{ action(PASS/REJECT), note? }`，要求 Idempotency-Key；REJECT 时 note 必填。
- PASS：行→CHECKED，并执行与直接 PASS 相同的待检→可用状态转换；REJECT：行保持 EXCEPTION、库存保持待检，记录处理信息且禁止再次 resolve。
- resolve 使用状态条件更新保证只处理一次；并发失败返回 `QUALITY_CHECK_ALREADY_RESOLVED`，本端点不新增 `INSUFFICIENT_STOCK` 或 `VERSION_CONFLICT`。
- REJECT 后 Receipt 保持 CHECKING，不能进入 DONE；后续退货/报废批次负责终结该行。
- 错误：QUALITY_CHECK_NOT_FOUND、QUALITY_CHECK_ALREADY_RESOLVED、QC_STATUS_INVALID。

### POST /api/putaway-todos/search
- 请求：`{ warehouseId?, materialId?, batchId?, keyword?, page?, pageSize? }`；keyword 匹配 receiptNo/materialCode/materialName/batchNo。
- 响应：`{ items: PutawayTodo[], total, page, pageSize }`；只返回 Receipt.status=PUTAWAY 且 receiptLine.status=CHECKED，默认质量通过时间 asc（先到先上架）。
- 扫 t=B 后的候选处理与质检一致：单候选直达，多候选列表选择，禁止任取第一条。

### GET /api/putaway-todos/{receiptLineId}/recommendations
- 响应 200：`LocationRecommendation[]`，只含同仓、ENABLED、DEFAULT；已有同 materialId 的正库存库位优先，再按 location.code asc。
- 无合格库位返回空数组，不虚构推荐；本批不校验容量。

### POST /api/putaway-records
- 请求：`{ receiptLineId, toLocationId, scannedLocationCode, expectedInventoryVersion }`，要求 Idempotency-Key。
- `scannedLocationCode` 必须解析到 `toLocationId`；目标必须同仓、ENABLED、DEFAULT。允许选择非第一推荐项，但仍必须通过资格校验。
- 本期整行上架，不接收 quantity；同一事务内 staging 可用库存 `-quantity`、目标库位 `+quantity`，写同组两条流水并创建 PutawayRecord。
- 成功：行→PUTAWAY_DONE；全部行完成且无未处理 EXCEPTION 时 Receipt→DONE。
- 错误：RECEIPT_LINE_NOT_FOUND、PUTAWAY_LOCATION_INVALID、INSUFFICIENT_STOCK、VERSION_CONFLICT。
