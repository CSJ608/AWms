# 收货接口契约（草案 v0.3，C-03）

> 状态：**草案 v0.3（2026-08-10）**。v0.3：Receipt 状态流转显式化；strict 行级说明；幂等实现引用。
> 依据：通用规范 v1.8、数据模型 v0.4、标签规范 v0.14、ADR-003。

## 一、流程与规则
1. 收货提交支持无预建单与有预建单两种上下文。
2. 一致性策略：PO=STRICT（逐行 实收==应到，行不可拆分；同单不同行可分次收货）；PR/OT=LENIENT（按实收、diff 累计、允许超收）。
3. 行匹配（有预建单）：优先 orderLineId（扫外标签 ol 直接定位）；无 ol 按 materialId（同物料多行歧义 → 400）。
4. 批控必须批次：t=B 复用原批次（生产退料：原批次复用但按“待检”新建库存主体）；t=S 带 rb/pd 生成新批次；否则 BATCH_REQUIRED。
5. 唯一码：清单勾销；不在单 UNIQUE_CODE_NOT_IN_ORDER；重复 UNIQUE_CODE_ALREADY_RECEIVED。
6. 拍照：附件先上传拿 uploadId，提交带 photos。
7. 幂等：Idempotency-Key（通用规范 2.6，IdempotencyRecord 表实现）。
8. 入账：同一事务——内部批次 → 待检主体 → staging 物理库存 → 流水（外部操作）。

## 二、Receipt 状态流转（2026-08-10 显式化）
```
创建 ──► RECEIVING ──► CHECKING ──► PUTAWAY ──► DONE
```
| 状态 | 进入条件 |
|---|---|
| RECEIVING | 收货提交创建 |
| CHECKING | 首次质检提交（任一收货行执行 quality-check） |
| PUTAWAY | 全部收货行 CHECKED（含 EXCEPTION 已 resolve 为 PASS） |
| DONE | 全部收货行 PUTAWAY_DONE，且无未 resolve 的 EXCEPTION |

- 行状态：RECEIVED → CHECKED（质检 PASS）→ PUTAWAY_DONE（上架完成）；EXCEPTION 分支待 resolve。
- 入库单 RECEIVED 推进：见入库单契约 v0.3（同事务方案 A）。

## 五、端点详述
### POST /api/receipts（核心）
- 有预建单：{ warehouseId, inboundOrderId, lines: [{ orderLineId?, materialId, quantity }], photos? }
- 无预建单：{ warehouseId, sourceDocType?, sourceDocNo?, lines: [{ materialId, batchId?, batchProps?, quantity }], photos? }
- 响应 201：Receipt。错误：VALIDATION_ERROR、ORDER_NOT_FOUND、ORDER_VOIDED、ORDER_STATUS_INVALID、ORDER_LINE_MISMATCH、QTY_MISMATCH_STRICT、UNIQUE_CODE_NOT_IN_ORDER、UNIQUE_CODE_ALREADY_RECEIVED、BATCH_REQUIRED、MATERIAL_NOT_FOUND、WAREHOUSE_NOT_FOUND、NUMBER_EXHAUSTED、UNAUTHORIZED/FORBIDDEN。
### GET /api/receipts
- 固定参数：status、warehouseId、receiptNo、dateFrom、dateTo、page、pageSize。
- 支持 filter DSL；**字段白名单**：receiptNo、warehouseId、inboundOrderId、sourceDocType、sourceDocNo、status、operatorId、occurredAt。
- **排序白名单**：receiptNo、status、occurredAt；默认 occurredAt desc。
### GET /api/receipts/{id}
- 响应 200：Receipt。错误：RECEIPT_NOT_FOUND（404）。
### GET /api/quality-todos
- 参数：warehouseId、page、pageSize。响应：行级待检（receiptLine.status=RECEIVED）。
### POST /api/receipt-lines/{lineId}/quality-check
- 请求：{ result, checkedQty, exceptionReason?, photoIds? }。PASS→CHECKED/主体可用；EXCEPTION→记录待 resolve。
- 错误：RECEIPT_LINE_NOT_FOUND、QC_STATUS_INVALID、RECEIPT_STATUS_INVALID。
### POST /api/quality-checks/{checkId}/resolve
- 请求：{ action(PASS/REJECT), note? }。PASS→可用；REJECT→记录备注、主体保持待检（本期）。
- 错误：QUALITY_CHECK_NOT_FOUND。
### GET /api/putaway-todos / recommendations / POST /api/putaway-records
- 同 v0.2（上架：行=CHECKED；目标 type=DEFAULT；同事务 物理库存 staging→目标+流水）。
