# 收货接口契约（草案 v0.2，C-03）

> 状态：**草案 v0.2（2026-08-10）**。v0.2：ReceiptLine 增加 orderLineId；行匹配优先 orderLineId（扫标签 ol 直接定位，消除同物料多行歧义）。
> 依据：通用规范 v1.3、数据模型 v0.4、收货链工作流 v0.3.2、标签规范 v0.11、ADR-003。

## 一、流程与规则（2026-08-10 确认）

1. **收货提交**：支持无预建单与有预建单两种上下文；同一套入账逻辑。
2. **一致性策略**：PO=STRICT（逐行 实收==应到）；PR/OT=LENIENT（按实收，记录 diff，允许超收）。
3. **行匹配（有预建单）**：**优先 orderLineId**（扫外标签带 ol 时直接定位，无需手动选行）；无 ol 时按 materialId 匹配，**同物料多行歧义时返回错误要求带 ol 或选行**。
4. **批控物料必须批次**：扫描 t=B 复用原批次；t=S 带 rb/pd 生成新批次；否则 BATCH_REQUIRED。
5. **唯一码**：预建单行有清单时扫一个勾一个；不在清单 UNIQUE_CODE_NOT_IN_ORDER；重复 UNIQUE_CODE_ALREADY_RECEIVED。
6. **拍照**：附件先上传拿 uploadId（附件契约），收货提交时带 photos。
7. **提交幂等**：Idempotency-Key。
8. **入账**：同一事务——创建内部批次（如需要）→ 库存主体（待检）→ 物理库存（staging）→ 流水（外部操作）。

## 四、端点详述

### POST /api/receipts（核心）
- 请求（有预建单）：`{ warehouseId, inboundOrderId, lines: [{ orderLineId?, materialId, quantity, uniqueCodes? }], photos? }`
  - `orderLineId`：扫外标签带 ol 时提供，**直接定位行**；否则按 materialId 匹配（同物料多行歧义 → 400 VALIDATION_ERROR 提示）。
- 请求（无预建单）：`{ warehouseId, sourceDocType?, sourceDocNo?, lines: [{ materialId, batchId?, batchProps?, quantity }], photos? }`
- 响应 201：Receipt。错误：VALIDATION_ERROR、ORDER_NOT_FOUND、ORDER_VOIDED、ORDER_STATUS_INVALID、ORDER_LINE_MISMATCH、QTY_MISMATCH_STRICT、UNIQUE_CODE_NOT_IN_ORDER、UNIQUE_CODE_ALREADY_RECEIVED、BATCH_REQUIRED、MATERIAL_NOT_FOUND、WAREHOUSE_NOT_FOUND、NUMBER_EXHAUSTED、UNAUTHORIZED/FORBIDDEN。

### GET /api/receipts
- 筛选：`status`、`warehouseId`、`receiptNo`、`dateFrom`、`dateTo`、`page`、`pageSize`。

### GET /api/receipts/{id}
- 响应 200：Receipt。错误：RECEIPT_NOT_FOUND（404）。

### GET /api/quality-todos
- 参数：`warehouseId`、`page`、`pageSize`。响应：行级待检（receiptLine.status=RECEIVED）。

### POST /api/receipt-lines/{lineId}/quality-check
- 请求：`{ result, checkedQty, exceptionReason?, photoIds? }`。
- PASS：行→CHECKED；主体 待检→可用（状态变更流水，组内=0）。
- EXCEPTION：行→EXCEPTION；记录质检单，待主管 resolve。
- 错误：RECEIPT_STATUS_INVALID、QC_STATUS_INVALID、RECEIPT_LINE_NOT_FOUND。

### POST /api/quality-checks/{checkId}/resolve
- 请求：`{ action(PASS/REJECT), note? }`。PASS→可用；REJECT→记录备注、主体保持待检（本期）。
- 错误：QUALITY_CHECK_NOT_FOUND（404）。

### GET /api/putaway-todos
- 参数：`warehouseId`、`page`、`pageSize`。响应：行级待上架（receiptLine.status=CHECKED 且未上架）。

### GET /api/putaway-todos/{receiptLineId}/recommendations
- 响应：LocationRecommendation[]（同物料集中 > 空库位按编码序，理由后端生成）。

### POST /api/putaway-records
- 请求：`{ receiptLineId, toLocationId, quantity, recommendedLocationId? }`。
- 规则：行=CHECKED；目标 type=DEFAULT；同一事务 物理库存 staging→目标 + 流水。
- 响应 201。错误：RECEIPT_LINE_NOT_FOUND、PUTAWAY_LOCATION_INVALID、RECEIPT_STATUS_INVALID、INSUFFICIENT_STOCK、VERSION_CONFLICT。
