## 一、前端要做什么（本期范围）

### A. Web 后台（桌面浏览器）
1. 登录 + 会话（Bearer token，独立账号；401 静默刷新重放）
2. 系统管理：用户/角色/权限/菜单（**模块注册表驱动**，登录一次返回 permissions+menus）
3. 主数据：物料（searchCode/导入导出）、仓库、库位、批次（只读）、来源
4. 入库链管理：入库单（创建/列表/作废）、收货单查看、质检/上架待办
5. 库存：库存（主体/汇总）、库位库存、库存流水（含事务组）
6. 工作台：聚合接口（KPI + 待办 + 最近流水）
7. 打印：单据二维码/外标签/唯一码/批次标签（Web PDF + 打印中心）
8. 附件：收货照片查看
9. i18n 中英；亮色主题；**通用筛选区（SearchField[] 元数据驱动 + filter DSL）**

### B. PDA 作业（移动 Web / PWA，与 Web 同一代码库）
1. 我的作业入口（收货/质检/上架，按角色过滤）
2. 收货流程：扫单/新建 → 选类型 → 行录入（扫码+大键盘+连扫累加）→ 确认（差异+拍照）→ 打印回执
3. 质检、上架流程（待办 → 扫码确认 → 提交；上架含推荐库位）
4. 扫码：**后端统一解析**（POST /api/scan/parse）+ 外部条码兜底；离线本期不做
5. 打印：批次标签 PDA 单张（扫码即打印即贴，PDA 端驱动打印机）

## 二、技术约束（已定，不争论）

- 单一前端代码库，Web + PDA（PWA）；扫码枪=键盘输入
- 视觉：中性简洁 + 语义色；PDA 浅色高对比、大触控 ≥48px、声音反馈
- **mock 数据层先行**（与契约严格一致），后切真实 HTTP
- **通用平台能力**：运行时元数据端点（GET /api/meta/fields/{resource}）、通用 ReferencePicker（快捷搜索+完整弹窗）、通用列表页（分页+筛选+排序）、filter DSL 映射、sort 白名单
- 认证：不做 OAuth（ADR-005）；Bearer token
- 数据规模：SKU ≤10 万（分页）、日单据 ≤2000、用户 ≤50

## 四、请前端 AI 回答

### A. 技术选型意见
- **建议基线**：React 19 + Vite + TS strict + Tailwind v4 + shadcn/ui + TanStack Query + RHF/zod + TanStack Table + i18next + Vitest + RTL。确认或提替代（说明理由与成本）。
- PDA：同一代码库移动端 Web + PWA 是否可行？扫码枪 HID 键盘输入兼容性？**PDA 单张打印（蓝牙/网络热敏）的实现边界与方案**？
- 通用能力实现建议：SearchField[] 驱动筛选区、ReferencePicker（快捷搜索+完整弹窗）、运行时元数据渲染、filter DSL 前端映射（字段/操作符/值类型）、sort 白名单。
- 性能：10 万 SKU 分页 + 防抖 + 查询缓存是否够；是否需要虚拟滚动；工作台聚合接口是否满足。
- PWA：本期不做离线，是否预留 manifest/service worker。

### B. 对界面规格 / 标签规范 / 契约的意见
- 三份界面规格（首页/收货 PDA/基础数据）冲突/缺口/建议
- 标签规范 v0.13（外标签/唯一码/批次标签/ol 行引用/贴标签姿势 B）前端实现建议
- 契约：字段命名/DTO/错误码/分页/筛选/扫码/打印 是否符合前端使用习惯，是否有缺口

### C. 输出
《前端开工评审意见》：逐条（冲突/缺口/建议/无异议）+ 技术选型结论。
