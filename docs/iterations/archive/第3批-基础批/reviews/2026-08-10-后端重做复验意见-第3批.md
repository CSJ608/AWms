## 一、阻塞项（必须修复）

### B-01 迁移：文件齐备但“可应用”无任何验证；集成测试项目为空

- 严重程度：P1。

### B-02 登录：新库无任何可登录账号（无 User 种子），登录闭环不可演示
- 证据：`AWms.Infrastructure/Data/AWmsDbContext.cs` SeedData 仅种子 Roles/Permissions/RolePermissions/Menus，**无 `User` 种子**；UsersController 全部 `[Authorize]`，无匿名建号路径。新库上 login 永远 LOGIN_FAILED（无用户），用户管理又需要登录 → 死锁。
- 规范 §2.5 明确“管理员初始密码用环境变量注入 + 首启重置，且重置逻辑要有测试” —— 未实现。
- 严重程度：P0（直接击穿本批可演示工作流“登录”）。

### B-03 编号原子自增：SQL 在 PostgreSQL 上无法执行（占位符/参数未绑定）
- 证据：`NumberingService.NextAsync` 用 `_db.Database.GetDbConnection().CreateCommand()` 执行
  `UPDATE "Sequences" ... WHERE "Type" = {0} AND "ScopeKey" = {1} AND "BizDate" = {2} RETURNING "LastNo"`，
  参数为 `cmd.CreateParameter()`（Npgsql 无名参数）。**Npgsql 不识别 `{0}` 占位符**（那是 EF `FromSqlRaw/ExecuteSqlRaw` 的替换语法，此处绕过了 EF），真实 PG 上必然语法错误；INSERT...ON CONFLICT 分支同样问题。
- 后果：任何 `NextAsync`（含 IMPORT_TASK 取号、批次取号）在真实后端 100% 失败 → precheck/导出创建任务即报错。
- 并发取号测试、NUMBER_EXHAUSTED 测试均不存在（NumberingServiceTests 仅 5 个规则注册/格式用例）。汇报自认“待集成测试”，但**实现本身未在 PG 上跑过**。
- 严重程度：P0。

### B-04 filter DSL：API 层完全未接线，QueryService 是死代码
- 证据：`MasterDataService` 的 SearchMaterials/Warehouses/Locations/Sources/Batches 五个方法**从不读取 `request.Filter`**（全文无 `request.Filter` 引用）；`QueryService` 仅被 DI 注册与单测使用。`POST /api/{resource}/search` 带 `filter` 时被静默忽略、返回未过滤数据（数据正确性问题）；白名单外字段 400 在真实 API 上永远不触发。
- QueryService 自身实现也有缺陷：
  1. `contains/startsWith`：`FilterCondition.Value` 经 JSON 反序列化为 `JsonElement`，`BuildStringMethod` 判断 `value is not string` → 直接跳过（静默不筛）；
  2. `isNull/isNotNull` 对非空值类型（bool/enum/int）`Expression.Constant(null, 值类型)` 构造即抛异常 → 500；
  3. `between` 对 `DateOnly` 上界少一天（`< upper` 而非 `< upper.AddDays(1)`）；
  4. 嵌套 `and/or` Groups 被丢弃（`if (subExpr is Expression) continue;` 恒 false，计算结果未合并）；
  5. 默认主数据排序分支未追加 `id` 兜底（QueryService.ApplySorting else 分支仅 OrderBy，无 ThenBy id；MasterDataService 各自手写了 ThenBy id，但 QueryService 声称的唯一性兜底实现不完整）。
- 单测仅 5 个（白名单 400、非法排序、分页、稳定排序），**无 in/notIn/between/contains/isNull/数值/日期筛选用例**，汇报“全13个操作符实现”不实。
- 严重程度：P0（B-04 核心能力未实现）。

### B-06 导出：filter/sort 仍未生效；异步实现有运行时风险；状态机无 PROCESSING
- 证据 1：`ImportExportController.CreateExport` 构造 `FilterRequest(..., 1, request.PageSize)` —— **丢弃 `ExportRequest.Filter` 与 `ExportRequest.Sort`**；`ImportExportService.CreateExportAsync` 也只处理 keyword/status/sort/pageSize，**不处理 filter DSL**。汇报“filter/sort/pageSize 生效”不实。
- 证据 2：`Task.Run` 后台任务闭包捕获**请求作用域 `AWmsDbContext`**，请求结束即 dispose → 后台 `SaveChangesAsync` 大概率 ObjectDisposedException → 任务 FAILED。
- 证据 3：枚举无 `PROCESSING`（`ImportTaskStatus` 仅 PRECHECKING/PRECHECKED/EXECUTING/DONE/FAILED），导出用 `PRECHECKING` 冒充；契约要求“任务创建即返回 PROCESSING → DONE”。
- 证据 4：`ImportTaskResponse` **无 `failures` 字段**，precheck 失败明细不 inline 返回（契约要求 failures 固定 inline ≤200，超出给 failReportUrl）；前端 `ImportTask.failures?` 永远拿不到。
- 证据 5：导入 execute 真实入库已实现（同事务重校验 + 建 Material），但**两个核心测试被 `Skip`**（“Requires PostgreSQL”），无任何集成/E2E 验证。
- 严重程度：P0（导出核心要求未达成）/ P1（异步与失败明细契约）。

### B-07 幂等：仅建表建类，未接线任何端点，无测试
- 证据：`IdempotencyService` 与 `IdempotencyRecords` 表存在，但 grep 全仓无任何控制器读取 `Idempotency-Key` 或调用 TryGet/Store；无 IdempotencyServiceTests。汇报 B-07 标 ✅ 不实。
- 严重程度：P1。
