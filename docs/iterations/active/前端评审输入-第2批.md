# 前端评审输入：任务范围与技术选型（第2批，2026-08-10）

> 用途：给**前端 AI** 的《开工评审意见》输入包。
> 请通读"参考文档"后输出《前端开工评审意见》：**A 技术选型意见 + B 对界面规格/标签规范的意见 + C 结论**，逐条列出（冲突点 / 缺口 / 建议 / 无异议）。
> 意见提交给协调者（Codex）汇总 → 用户裁决 → 更新 ADR-004 与契约。

## 一、前端要做什么（本期范围）

### A. Web 后台（桌面浏览器）

1. 登录 + 会话（独立账号，token）
2. 系统管理：用户 / 角色 / 权限 / 菜单（**模块注册表驱动**，新增模块不改框架）
3. 主数据：物料（含**导入导出**）、仓库、库位、批次、来源（供应商/车间）
4. 入库链管理：入库单（预建单）管理、收货单查看、质检/上架待办
5. 库存：库存（主体）、库位库存（物理库存）、库存流水
6. 工作台（首页）：KPI 4 个 + 待办列表 + 最近流水 + 快捷操作
7. 打印：收货回执 / 批次标签（浏览器打印 PDF，内置模板）
8. 附件：收货照片查看
9. i18n 中英；亮色主题先行，暗色后置

### B. PDA 作业（移动 Web / PWA，与 Web 同一代码库）

1. 我的作业入口：收货 / 质检 / 上架（按角色过滤）
2. 收货流程：定位上下文（扫单/新建）→ 选入库类型 → 行录入（扫码 + 大键盘 + 连扫累加）→ 确认提交（差异提示 + 拍照）→ 结果页（打印回执）
3. 质检流程：待办 → 扫码确认 → 提交
4. 上架流程：待办 → 推荐库位（附理由）→ 扫库位码 → 提交
5. 扫码输入：扫描枪 = 键盘输入模式；**AWMS1 标签解析** + 外部条码（EAN/Code128/GS1）兜底
6. 离线：本期不做（后置）

## 二、技术约束（已定，不争论）

- 单一前端代码库，Web + PDA 双端（PWA）
- 扫码枪键盘输入模式
- 视觉：中性简洁 + 语义色（待检 amber / 可用 emerald / 异常 red）；PDA 浅色高对比、大触控 ≥48px、声音反馈（成功/失败）
- **mock 数据层先行**（与契约严格一致），后切真实 HTTP（MWms 已验证此模式）
- 测试：单元 + 组件测试；lint/build 门禁
- 数据规模：SKU ≤10 万（列表服务端分页）、日单据 ≤2000、用户 ≤50

## 四、请前端 AI 回答

### A. 技术选型意见

- **建议基线**：React 19 + Vite + TypeScript strict + Tailwind v4 + shadcn/ui（沿用 MWms/星云基线，中性简洁视觉）
- 请确认或提出替代（如 Vue / Next / 其他 PDA 方案），说明理由与成本
- PDA：同一代码库移动端 Web + PWA 是否可行？扫码枪 HID 键盘输入的兼容性？是否需要 WebView 壳？
- 数据请求/状态：TanStack Query 是否合适（10 万 SKU 分页缓存）
- 表单/表格：RHF + zod / TanStack Table
- i18n / 主题：i18next / next-themes
- 测试/构建：Vitest + RTL / Vite；CI 门禁
- 性能：列表分页 + 防抖搜索 + 查询缓存是否足够；是否需要虚拟滚动
- PWA：本期不做离线，是否预留 manifest / service worker

### B. 对界面规格的意见

- 三份规格（首页 / 收货 PDA / 基础数据）冲突 / 缺口 / 建议
- 标签规范 v0.4 解析在前端的实现建议（前缀解析、外部条码兜底）
- 模块注册表 + 权限在前端的实现建议（路由/菜单/按钮三级）

### C. 输出

《前端开工评审意见》：逐条（冲突 / 缺口 / 建议 / 无异议）+ 技术选型结论。
