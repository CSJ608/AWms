# 迭代计划 - 第4批：收货链

> 状态：**实现阶段 v0.6（2026-08-21）**。D-01~D-03 已定稿，前后端复核均无异议，第 4 批契约已锁定；**前后端已获得实现开工许可**。
> 目标：用一条可演示工作流跑通“Web 建单 -> PDA 收货 -> 质检 -> 上架 -> 可用库存落位与流水追溯”。
> 集成负责人：前端 AI（沿用规章制度默认约定）。

## 一、批次目标

本批只交付一条纵向闭环，不以端点数或页面数作为完成标准：

```text
Web 创建入库单并生成单据码
  -> PDA 扫码收货并拍照
  -> 系统生成批次、待检库存和收货流水
  -> PDA 质检（异常由主管 Web 处理）
  -> PDA 获取推荐库位并扫码上架
  -> 收货单 DONE、目标库位形成可用库存、流水完整
```

## 二、已确认裁决

1. 第 4 批保持为一个完整收货链批次，不拆成两个独立批次；内部设置设计契约、实现、联调验收三个里程碑。
2. PO 必须引用预建入库单；PDA 无单新建只允许 PR/OT。预建 PR/OT 仍可正常收货。
3. Web PDF 与 PDA 二维码/内容预览是本批打印验收基线；PDA 真机打印仅做 P-01 spike，不阻塞验收。
4. 质检 `REJECT` 后，收货行保持 `EXCEPTION`，库存留在暂存库位且保持待检，禁止上架；退货/报废处置后置。主管 `PASS` 后才转为可用。
5. 推荐库位限定同仓、启用、`DEFAULT`：优先已有同物料库存的库位，再按库位编码升序；允许改选其他合格库位。本批无容量模型，不判断“已满”。
6. Web 入库模块在 `/inbound` 下提供“入库单 / 收货记录 / 质检异常”三个视图。
7. Web 新建入库单和单据详情使用应用内工作标签承载，不使用弹窗或列表底部表单；新建成功后当前标签原位转为单据详情。
8. 来源规则：PO 必须选择启用供应商；PR 必须选择启用生产车间；OT 来源可空，填写时必须引用启用来源。
9. Web 标签打印按单据行触发参数对话框；本批不做多行勾选。外标签输入 count，唯一码输入 count/qtyPerCode 并展示登记数量差异。
10. PDA 扫批次标签定位质检/上架待办：1 条自动打开，多条展示候选列表，0 条提示无匹配。

## 五、批末主验收场景

### 5.1 黄金路径

1. 仓管在 Web 创建一张批控物料 PO 入库单，数量 `200`，生成单据二维码。
2. 作业员在 PDA 扫单据码，实收 `200` 并上传一张照片；重复提交不产生重复收货。
3. 系统生成内部批次，在 `STAGING` 库位增加 `200` 待检库存并记录收货流水。
4. 作业员质检 PASS；待检库存减少 `200`、可用库存增加 `200`，同一事务组内合计为 `0`。
5. PDA 推荐同仓启用 `DEFAULT` 库位；作业员扫码确认上架。
6. 暂存库位可用库存归零、目标库位增加 `200`；收货单进入 `DONE`。
7. 批次标签按每张 `10` 件生成 `20` 张，可在 PDA 预览；收货回执可在 Web 下载 PDF。

### 5.2 必测分支

- PO 数量与应到不一致：拦截且不产生批次、库存或流水。
- 无单 PR/OT：允许按实收提交；无单 PO：前端不提供入口且后端拒绝。
- 唯一码不在单据、重复唯一码：拦截且不重复入账。
- 质检异常：原因和照片可查；主管 PASS 后继续，REJECT 后保持待检且不可上架。
- 上架到跨仓、停用或非 `DEFAULT` 库位：拦截；并发版本冲突返回 `VERSION_CONFLICT`。
- 附件类型/大小非法、已关联附件删除：按契约失败。
- 打印不可用：业务已提交结果不回滚，仍可重新打开预览或 Web 补打。

## 六、明确不做

- PWA 离线、摄像头扫码、托盘码、唯一码无单全局登记。
- 库位容量/满位判断、AGV 推荐、仓内移库。
- 免检/抽检规则、退货/报废处置流程。
- PDA 真机打印作为验收门禁、打印模板配置界面、手动不均匀拆标。
- 库存查询页面与工作台（第 5 批）、系统管理 UI、服务端错误文案 i18n。

## 七、风险与控制

| 风险 | 控制 |
|---|---|
| 入库链实体和事务多，单批体量大 | 保持一个批次验收，但按收货入账、质检、上架三个纵向切片逐段集成 |
| 锁定契约存在 DTO 缺口 | M4.1 修订为草案，双向评审后重新锁定，未锁定不得开工 |
| 打印硬件不确定 | PDF/二维码预览为正式降级；P-01 spike 与业务验收解耦 |
| 扫码设备差异 | 先支持键盘楔入式扫描枪和手工输入；摄像头扫码 P-20 后置 |
| 库存写入并发与一致性 | PostgreSQL 集成测试验证幂等、乐观锁、同事务流水和库存守恒 |
| 工作标签是新增框架能力 | 本批只实现打开、聚焦、切换保活、关闭确认和路由同步；不扩展拖动排序、固定或跨会话恢复 |
