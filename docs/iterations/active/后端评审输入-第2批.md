# 后端评审输入：任务范围与技术选型（第2批 v0.1，2026-08-10）

> 用途：给**后端 AI** 的《开工评审意见》输入包。
> 请通读"参考文档"后输出《后端开工评审意见》：**A 技术选型 + B 数据模型/契约可落地性 + C 并发一致性/边界 + D 结论**，逐条（冲突点 / 缺口 / 建议 / 无异议）。
> 意见提交给协调者（Codex）汇总 → 用户裁决 → 更新契约/ADR。

## 一、后端要做什么（本期范围）

1. **框架**：登录/用户/角色/权限/菜单/模块注册表（Bearer token，不做 OAuth——ADR-005）
2. **主数据**：物料（searchCode/默认装箱量/导入导出）、仓库、库位、批次（系统自动生成）、来源
3. **入库链**：入库单（统一表+类型路由，作废重建）、收货（严格/宽松策略、唯一码勾销、批次生成、拍照）、质检（PASS/EXCEPTION+resolve）、上架（推荐库位）
4. **库存**：库存/库位库存/流水/事务组、汇总查询、复式记账、物理库存乐观锁
5. **工作台**：聚合接口
6. **平台能力**：编号服务（规则注册/批量分配/同事务）、查询平台（filter DSL/sort 白名单/字段元数据端点/keyword）、标签解析（AWMS1+外部条码）、附件（本地存储）、打印（PDF 生成+留痕）、导入导出（两阶段/异步）

## 二、技术约束（已定）

- **.NET 10（LTS）+ ASP.NET Core Web API + EF Core + PostgreSQL**
- 附件本地文件存储 + 元数据表；打印后端生成 PDF（浏览器）+ PDA 单张返回数据
- 编号服务：Sequence 表 + 原子自增 + 规则注册（通用规范 2.9）
- 查询平台：QueryParser（字段/操作符白名单 + 参数化）+ 运行时元数据端点
- 认证：Bearer token（JWT 或等值，含 sub/exp/roles/permissions）

## 四、后端评审重点（请逐项给出意见）

### A. 技术选型
- .NET 10 + EF Core + PostgreSQL 是否合适；EF Core 迁移策略（版本化、绝不让 AI 在非空表乱改结构）
- 附件本地存储路径/权限；PDF 生成方案（模板 + 二维码）

### B. 数据模型可落地性
- 实体/字段/关系是否完整可建表；唯一约束（batch(materialId,batchNo)、subject(仓库+物料+批次+状态) 等）
- Sequence 表 + 原子自增（UPDATE...RETURNING）并发正确性；编号规则注册表实现方式
- 批次系统自动生成：收货时创建内部批次 + 来源属性；生产退料复用原批次

### C. 并发与一致性（重点）
- 收货/质检/上架同一事务内"更新物理库存 + 追加流水"；复式记账（内部操作组内求和=0）如何保证
- 物理库存 version 乐观锁；并发收货/上架冲突（VERSION_CONFLICT）
- 幂等键（Idempotency-Key）实现（重复请求返回首次结果）
- 唯一码生成+登记+打印同事务（防孤儿码）
- 严格/宽松数量策略的校验点；部分收货（行级）与单据状态推进

### D. 状态机与边界
- 入库单 CONFIRMED/RECEIVING/RECEIVED/VOIDED；收货行 RECEIVED/CHECKED/EXCEPTION/PUTAWAY_DONE；作废留痕
- 边界：超收（宽松）、唯一码重复/不在本单、编号耗尽（NUMBER_EXHAUSTED）、删除引用保护
- 查询平台：filter DSL 解析与参数化防注入；字段/操作符白名单机制；keyword 搜索实现（code/name/searchCode）

### E. 安全
- 密码哈希（Argon2id/bcrypt）、token 生命周期与刷新、三级权限（路由/菜单/操作）校验点
- 附件上传校验（类型/大小/路径安全）

### F. 其他
- 导入导出两阶段（预校验不落库→全部通过才执行）的事务边界；异步导出任务
- 打印 PDF 内容与标签规范一致（AWMS1 content + 可读文字）
