# 《前端开工评审意见》（第2批 契约批 C-05）

> 评审人：hermes（前端 AI）｜日期：2026-08-10
> 通读范围：docs/api/ 全部 15 份 + 通用规范 v1.7、docs/design/ 4 份 + 3 份界面规格、docs/concepts/库存概念 v1.0、docs/product/框架设计 v0.2、docs/decisions/ADR-001~005、术语对照表、规章制度 §八、迭代计划第2批
> 逐条标注：**冲突 / 缺口 / 建议 / 无异议**。提交协调者（Codex）汇总 → 用户裁决。

## A. 技术选型

**A-1 无异议** — 建议基线整体确认：React 19 + Vite + TS strict + Tailwind v4 + shadcn/ui。与用户既有基线（星云管理后台）一致，机器环境 Node 26 + pnpm 11 兼容；Tailwind v4 用 `@theme` CSS 变量将视觉规范 token（靛蓝/emerald/amber/sky/red/slate + tabular-nums）映射为设计变量。

**A-2 无异议** — TanStack Query + RHF/zod + TanStack Table。补充两点实现约束：
- mock 先行建议用 **MSW**（browser + node）：handlers 严格按契约 DTO 编写，`VITE_USE_MOCK` 开关切换真实后端，天然覆盖 401 刷新重放、错误码分支等联调路径；比 in-memory 适配层更接近真实 HTTP 语义，且 Vitest 复用同一套 mock。
- 契约 DTO → `frontend/src/api/types` 手写 TS 类型（唯一事实来源），mock 层做运行时校验防漂移。

**A-3 无异议** — i18next（中英，UI 文案前端维护，符合通用规范 2.5）。**建议**：语言切换需同步 `Accept-Language` 请求头（后端错误文案按语言返回），i18n 初始化时挂进请求层；主题本期仅亮色，next-themes 可引入（成本低）或 CSS 变量 + `data-theme` 预留，暗色后置无痛。

**A-4 无异议** — Vitest + RTL。**建议**：平台能力（filter DSL builder、权限工具、decimal 处理、扫码输入协议、401 刷新队列）必须有单测，业务页至少冒烟 + 关键交互。

**A-5 无异议** — Web + PDA 同一代码库可行。**建议**：不是"响应式一套"，而是**双路由树**（`web/*` 与 `pda/*`）+ 共享组件层（表单/表格/扫码/通用能力）；PDA 独立布局（一屏一任务、底部固定主操作、≥48px 触控），两套路由按登录返回的 `menus.web / menus.pda` 注册表过滤渲染。

**A-6 建议（需裁决终端形态）** — 扫码输入抽象为 `ScanInput` 组件，三种输入源可插拔：① 硬件扫描枪/专用 PDA 扫描头 = keydown 协议（Enter 结尾 + 时间窗分组，防长按误扫）；② 摄像头扫描（手机/平板无扫描头时）= `BarcodeDetector` API + zxing-wasm 兜底；③ 全部汇聚到 `POST /api/scan/parse`。**缺口**：契约批未定义 PDA 终端形态（专用 PDA vs 手机/平板），影响扫码与拍照方案（`<input capture>`）。建议本期按"专用 PDA（扫描头=键盘输入）为主 + 摄像头方案作可选依赖"，前端接口抽象两层都支持。

**A-7 冲突（需用户裁决，阻塞范围）** — **PDA 单张打印范围不一致**：
- ADR-004「打印：本期浏览器打印（PDF）+ 内置模板；**PDA 打印后置** ✅已确认」
- 前端评审输入 B.4 本期范围含「打印：批次标签 PDA 单张（扫码即打印即贴，**PDA 端驱动打印机**）」
- 打印契约已含本期端点 `POST /api/print/batch-label-one`（PDA 单张，姿势 B）
- 标签规范 v0.13 决议：默认姿势 B（批次标签贴箱，批次级操作物理锚点）

浏览器 PWA 驱动热敏打印机的能力边界：网络打印机（HTTP/TCP9100）受浏览器协议限制且需打印机支持；Web Bluetooth 对 SPP/热敏支持有限且 iOS 不可用；原生桥超出 PWA。**建议**：本期锁定"打印数据接口（`batch-label-one` 返回 content/readableText）+ 打印方案 spike 验证（首选网络热敏 HTTP 协议）"，PDA 界面先提供"打印内容预览 + 二维码"降级；若现场打印机不可网络化，PDA 单张打印顺延下一批。**需同步修订 ADR-004 与标签规范"待现场验证"项。**

**A-8 无异议** — 性能：10 万 SKU 是服务端分页（非客户端渲染 10 万行），分页 + 防抖（300ms）+ TanStack Query 缓存足够，**不需要虚拟滚动**；ReferencePicker 候选限 20 条 + keyword；工作台聚合一次返回满足首页。补充：列表 pageSize ≤ 100；导出全量走异步任务（导入导出契约已支持）。

**A-9 建议** — PWA 预留：本期用 vite-plugin-pwa 出 manifest（standalone/图标/theme-color）+ 最小 SW（仅静态壳缓存，**不缓存 API**），离线逻辑后置。成本低，避免后期补 SW 结构改造。

**A-10 建议** — 路由 react-router v7：**路由表静态注册 + 按 menus/permissions 过滤渲染**（不动态生成路由，避免动态 import 复杂度和 404 兜底缺失）；未授权模块路由守卫 + 未知路径 404。

**A-11 建议** — 目录结构：`src/platform/`（SearchField 渲染器、filter DSL builder、ReferencePicker、DataTable 通用列表、导入导出弹窗、打印中心、权限工具、401 刷新队列）与 `src/modules/`、`src/pda/`、`src/mocks/`（MSW）、`src/api/` 分离，呼应 ADR-001 模块注册表驱动（新增模块不动框架）。

**A-12 建议** — 数量 decimal 字符串**透传不换算**，显示用等宽数字；前端计算（连扫累加、差异展示）用 decimal.js 防浮点；时间 dayjs 本地化显示（UTC→本地），日期筛选按契约 yyyy-MM-dd。

**A-13 建议** — Idempotency-Key 在 API 层注入：按"用户动作"粒度生成并**重试沿用同一 key**（网络失败重发不产生重复单据），收货/质检/上架提交均适用。

## B. 界面规格 / 标签规范 / 契约

### B1 界面规格（3 份）

**B-1 无异议** — 首页工作台 v1.0 ↔ 工作台契约 v0.1 一一对应：KPI 4 个（待质检/待上架/异常/可用SKU）、待办三类、最近流水、快捷操作；空态/错误态/无权限态均定义了表现，可直接实现。

**B-2 无异议** — 基础数据物料页 v1.0 ↔ 物料契约 v0.3：字段、新建/编辑 Dialog、删除 AlertDialog + 引用保护 toast、导入导出两阶段（仅新增/全部通过才执行）与契约一致。

**B-3 冲突（版本滞后，需修订）** — 物料页筛选区规格（线框仅"编码 + 名称"两框，v1.0 于 08-09 定稿）早于通用规范 2.10（08-10 定稿）与物料契约 v0.3（keyword/labelType/status/batchControlled 可筛）。**建议**：物料页筛选区升级为 SearchField[] 元数据驱动（编码/名称/标签类型/状态 + keyword），或明确"基础筛选 + 高级筛选展开"；界面规格需修订并走评审。这是"通用筛选区"首个落地页，规格必须先行。

**B-4 缺口（关键）** — **质检/上架 PDA 无界面规格**：本期范围含质检、上架流程（待办 → 扫码确认 → 提交；上架含推荐库位、批次标签拆分打印 7.3 集成），但仅收货 PDA 有逐屏线框。质检（PASS/EXCEPTION + 原因 + 拍照 + resolve 主管入口）与上架（推荐库位展示/改选 → 拆分确认 → 打印 → 扫码确认）交互未定义。**建议**：补质检/上架 PDA 规格（或本期范围明确缩小）。

**B-5 缺口（关键）** — 本期范围含但**无界面规格**：入库单创建/列表/作废页（工作台"+ 新建入库单"直达）、打印中心、照片查看、系统管理（用户/角色）。**建议**：以物料页为模板，输出一份"通用列表页 + 通用 Dialog 表单"规格（与平台能力 SearchField/DataTable 一致），其余页面声明复用；比逐个画线框成本低且符合注册表驱动架构。

**B-6 缺口** — 批次"只读"页无规格，且契约无全量批次列表端点（仅 `GET /api/materials/{materialId}/batches`）。**建议裁决**：批次浏览 = 物料详情 tab，或补 `GET /api/batches`（keyword 分页）契约做独立搜索页。

**B-7 无异议** — 收货 PDA v1.0 屏幕流（定位上下文 → 选类型 → 行录入 → 确认 → 结果）与收货契约/标签规范 7.6 对齐。

**B-8 小冲突（示例过时）** — 收货 PDA 线框"批次 B260809-01"、首页线框"RCP-260809-001"为旧编号格式（yyMMdd+3）；通用规范 2.9 现为 RCP-**yyyyMMdd**-0001（4 位）、批次 **YYMMDD+3**（260810001）。不影响实现，但验收对照易混淆，**建议规格示例同步**。

**B-9 缺口** — PDA 无预建单 + 无外标签（盘点 OT / 手选）场景的**物料手选交互未定义**。建议：keyword 搜索弹窗（复用 ReferencePicker 轻量模式）。

**B-10 建议（表述修正）** — 规格"连扫自动 +1（非唯一码）"与标签规范 7.6 不一致：实际按 `defaultQtyPerLabel` 累加（如 10）。**建议规格改为"按每标签数量累加"**，避免实现歧义。

**B-11 建议** — 扫外标签带出的批次属性（rb/pd/ex）在行卡片上**回显/可确认**的交互未定义，建议补充（留档透明，符合"做错会拦住你"愿景）。

### B2 标签规范 v0.13

**B-12 无异议** — 整体结构（AWMS1 前缀 + 紧凑 JSON、rt/rc 查名不入码、ol 行引用、外标签=身份+默认值、拆分尾数 7.2、姿势 B 决议 7.5）。前端不直接解析标签（统一走 scan/parse + 打印契约），职责边界清晰。

**B-13 小冲突（示例过时）** — 唯一码示例 `BOX-260809-001`（yyMMdd+3）与通用规范 2.9 `UNIQUE_CODE = BOX-yyyyMMdd-0001`（4 位）不一致（v0.5 修订只改了批次号示例）。以 2.9 为准，建议同步示例。

**B-14 建议** — 姿势 B 的"扫码即打印即贴"UI 纪律（扫一箱打一张、打印机状态反馈）与打印失败/打印机离线的降级路径（提示 + 稍后补打）依赖 A-7 打印方案裁决，需在界面规格明确。

### B3 契约

**B-15 无异议** — 通用规范 2.1~2.8（envelope + 状态码、分页 `{items,total,page,pageSize}`、ISO UTC + decimal 字符串、Bearer + 401 静默刷新、错误码=判断钥匙）整体符合前端使用习惯。

**B-16 无异议** — 枚举与错误码 v1.5：状态机（入库单 CONFIRMED/RECEIVING/RECEIVED/VOIDED、收货行 RECEIVED/CHECKED/EXCEPTION/PUTAWAY_DONE）、前端分支码（QTY_MISMATCH_STRICT、UNIQUE_CODE_ALREADY_RECEIVED、ORDER_VOIDED、VERSION_CONFLICT）已覆盖收货关键路径。

**B-17 缺口** — **库存流水 reason 枚举未入枚举文档**：库存.md FieldMeta 引用"枚举文档"，但枚举与错误码.md 无 reason 表（RECEIPT/QUALITY_CHECK/PUTAWAY/状态变更…）。前端徽章与筛选 options 依赖。**建议补入枚举文档**。

**B-18 缺口** — 通用规范 2.10「ref 目标实体必须提供 keyword」**违反项：batches**（`GET /api/materials/{materialId}/batches` 无 keyword，也无全量列表）；而 stocks/location-stocks/ledgers 的 FieldMeta 均声明 `batchId: ref(batches)`。**建议**：补 `GET /api/batches`（keyword 分页）或明确批次选择器走"物料→批次"级联（契约注明，前端按级联实现）。

**B-19 缺口** — 入库单/收货列表**未声明 filter DSL 支持与字段/sort 白名单**（通用规范 2.10 说"主要列表启用"；物料/库存/仓库库位/来源已列，入库单/收货/工作台未列）。通用筛选区落到入库单列表时无依据。**建议补齐或注明"本期固定参数筛选"**。

**B-20 缺口** — 认证契约 `menus.web` 缺 **icon 字段**（框架设计 v0.2 声明菜单含图标）。**建议**：注册表加 `iconKey`，或前端按 moduleCode 映射图标（需拍板）。

**B-21 建议** — filter DSL 固化三点歧义：`in/notIn` 的 value 形态（数组）、`between` 对纯日期字段的边界（含当日全天？建议服务端按"当日 00:00 ~ 次日 00:00"处理）、sort 是否允许多列（示例为单元素数组，建议本期单列）。

**B-22 缺口** — 导入导出 `precheck` 响应"含 failures 明细列表**或** failReportUrl"二义。预校验报告 UI 需要固定形态：**建议 inline 返回 `FailureDetail[]`（≤200 条），超出给 failReportUrl**。

**B-23 缺口** — AttachmentItem DTO 示例缺 `thumbnailUrl`（列表说明提到"含 url/thumbnailUrl"）。照片查看网格需要，**建议 DTO 补全**。

**B-24 缺口** — 入库单 POST `lines[].uniqueCodes` 请求形态未定义（string[] 码值？count？）。**建议**：创建时不录码，由"唯一码打印"端点（打印契约 unique-labels 已支持按行登记+打印）生成——简化表单且与 7.1"唯一码收货前打印"一致；契约注明 uniqueCodes 由打印端点登记、创建接口不收。

**B-25 建议（待后端定）** — refresh 请求形态（Bearer 过期 token vs body refreshToken）标注"实现细节契约批后端定"：前端拦截器先按 Bearer 过期 token 实现 mock，联调对齐即可，不阻塞。

**B-26 无异议** — 标签解析契约：统一入口、UNKNOWN 200 返回（业务非错误）、warnings 不阻断（PDA 提示、动作接口把关）——设计正确，前端 ScanInput 全量走它。

**B-27 无异议** — 打印契约：AWMS1 content 与 readableText 由后端生成（前端不拼码）、拆分尾数后端算 N、PrintJob 统一形态（含收货回执）——前端职责轻。

**B-28 建议** — external-labels 请求 `materialId | materialIds` 二选一，建议统一为数组（表单与 mock 简单）。

**B-29 无异议** — 附件"先上传后关联"（photos/photoIds）、限制（≤10MB、jpg/png/webp、收货 ≤3 张）前端提前校验即可。

**B-30 无异议** — 工作台聚合一次返回（避免 5 请求）、warehouseId 可选 + todoLimit/ledgerLimit 参数、KPI 口径与各列表接口一致（"查看全部"可直达）。

**B-31 建议** — 401 静默刷新重放：**以 401 响应为准触发刷新**（不依赖本地 expiresAt 倒计时，避免时钟偏差），单飞刷新 + 并发请求排队重放由前端平台层实现；契约已满足。

**B-32 无异议** — 认证权限三级权限点（route/menu/action）与 menus 双端注册表：前端渲染侧边栏/PDA 入口按注册表过滤，封装 `hasPermission(code)` 工具；操作按钮按 action 权限显隐。

## C. 结论

**C-1 技术选型结论**：**确认建议基线**（React 19 + Vite + TS strict + Tailwind v4 + shadcn/ui + TanStack Query + RHF/zod + TanStack Table + i18next + Vitest + RTL），无替代方案；补充 8 项落地约束（A-2/A-3/A-5/A-6/A-9~A-13：pnpm、react-router v7、MSW mock 层、双路由树、ScanInput 抽象、PWA 预留、401 单飞刷新、平台能力目录、decimal.js + dayjs、Idempotency-Key 注入）。PDA 同库 + PWA **可行**（A-5/A-9）；性能方案**足够**（A-8）。

**C-2 需用户裁决的 3 项（前端开工范围依赖）**：
1. **PDA 单张打印**：范围冲突（A-7）——本期做（需打印方案 spike + 修订 ADR-004）还是后置（界面先降级预览）；
2. **界面规格补充方式**（B-4/B-5/B-6）：质检/上架 PDA、入库单页、打印中心、照片查看、系统管理——补线框或"通用列表页+通用表单"模板化（推荐后者）+ 物料页筛选区升级（B-3）；
3. **契约小修清单**（B-17/B-18/B-19/B-20/B-22/B-23/B-24/B-28）：批次 keyword、reason 枚举、入库单/收货白名单、menus icon、failures 形态、thumbnailUrl、uniqueCodes 形态、external-labels 参数统一——均为低风险修订，建议随评审一并锁定。

**C-3 契约总体判断**：15 份契约草案 + 通用规范 v1.7 **内部一致性良好，无颠覆性意见**，主体可锁定；上述裁决项经协调者汇总 → 用户决议 → 更新标准文档（ADR-004/契约/界面规格）后，前端即可按**最终版**开工（mock 先行，不依赖后端环境，符合规章制度 §八.3）。

**C-4 流程建议**：裁决结果与修订回执由协调者逐条回填本意见（沿用 C-05 门禁），前端以锁定后的契约 + 界面规格为实现基准；评审记录已按 §八.2 落盘 docs/reviews/。
