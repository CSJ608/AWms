# 迭代计划 - 第5批：PC平台体验与工程规范

> 状态：**设计阶段 v0.1（2026-08-22）**。本版本只开启设计与规范评审，**未开放前端/后端业务代码实现**。
> 目标：把 PC 全局布局、全局标签页、多语言治理和前后端工程规则设计清楚，为后续平台重构建立可验收基线。
> 基线提交：`e71f67be5c9863056ebf0e3dbc5875613e1e99f0`。

## 一、批次定位

第 5 批不是新业务工作流批次，而是 PC 平台体验与工程规范批次。它要解决三个问题：

1. PC 端从“左侧菜单 + 页面级上下文”升级为“顶部导航栏 + 全局标签页栏 + 内容栏”的三段式全局框架。
2. 将活动标签页状态提升到全局应用层，避免切换菜单时销毁用户正在处理的工作面。
3. 补齐前后端开发规范与 i18n 规则，防止布局、状态、契约调用、错误提示和枚举文案继续分叉。

本批遵守既有铁律：**界面规格与规范评审通过前，不修改 `frontend/`、`backend/` 业务代码**。本 PR 只新增文档。

## 二、已确认输入

1. PC 页面采用全局三段式布局：顶部导航栏、全局标签页栏、内容栏。
2. 顶部导航栏左侧固定 LOGO 与产品名称；右侧提供菜单搜索、多语言切换、用户头像 LOGO + 名称悬浮菜单。
3. 全局标签页栏固定两个 ICON：标签页、菜单；其余为活动标签页。
4. 活动标签页状态由全局应用层管理；切换菜单不得销毁已有活动标签页。
5. 入库管理等页面存在多语言缺失，需要统一前端 UI 文案、后端错误消息与枚举显示规则。
6. 需要分别形成前端开发规范草案与后端开发规范草案。
7. 非阻塞遗留：生产/失效日期未落库、GitHub Actions Node 20 deprecation warning、前端 Fast Refresh warnings。

## 四、非阻塞遗留评估

### 4.1 UI 生产/失效日期未落库

代码与契约初查显示：收货契约、前端 `BatchProps`、后端 `BatchPropsRequest`、`Batch`、`ReceiptLine` 均有 `productionDate` / `expiryDate` 字段，`ReceiptService` 也存在写入路径。因此该问题更像**特定场景的数据链路缺陷或口径争议**，不是第 5 批 PC 平台重构的设计缺口。

**建议**：不纳入第 5 批 M5.1/M5.2，单独开数据缺陷追踪。追踪时必须补齐：

1. 复现步骤、提交 payload、响应 DTO、批次表与收货行表实际值；
2. 判断是 UI 未提交、请求 DTO 丢失、批次复用策略覆盖，还是查询展示口径错误；
3. 如需契约变更，先修订 `docs/api/收货.md`，再走独立修复批/缺陷分支。

### 4.2 GitHub Actions Node 20 deprecation warning

当前应用运行时已经使用 Node 22，但 warning 可能来自 action 自身仍运行在 GitHub 托管运行时的 Node 20。第 5 批只把它列为 M5.2 工程治理项：逐个确认 action 版本说明，升级到支持新 Node 运行时的版本，并要求 CI 全绿。不在本设计 PR 中改 workflow。

### 4.3 前端 Fast Refresh warnings

按“组件文件只导出组件；常量、工具函数、路由注册项拆到独立文件”的规则治理。第 5 批 M5.2 先消除现有 warnings，再通过前端规范与测试防止回归。

## 五、验收标准

### 5.1 本 PR（设计门禁）验收

1. 当前分支基于 `main@e71f67b`，tracked 工作区只包含本批四个新增文档。
2. 不修改 `frontend/`、`backend/`、`.github/` 及任何业务代码。
3. 四份文档齐备：迭代计划、PC 全局布局规格、前端规范草案、后端规范草案。
4. 明确 M5.1/M5.2 门禁、验收标准、不做范围和三项非阻塞遗留的处置建议。
5. 用户完成文档评审；评审意见裁决并回写后，M5.1 才能通过。

### 5.2 M5.2（后续实现）验收基线

1. `1440x900` 与 `1024x768` 下三段式布局不重叠、不横向溢出；顶部导航与标签页栏行为符合规格。
2. 菜单搜索、语言切换、用户菜单、标签页打开/切换/关闭/保活均有测试或演示证据。
3. 从菜单反复进入不同模块，已有入库列表筛选、分页、新建表单输入不丢失。
4. Web 用户可见文案不出现硬编码中文/英文；中英文词条结构一致，缺失有 CI 或测试暴露。
5. 后端错误 message 按 `Accept-Language` 返回中/英；code、HTTP 状态、业务分支不因语言变化。
6. 枚举显示优先由前端按稳定值翻译；后端返回业务原因时使用稳定 reasonCode，避免把翻译职责混入数据契约。
7. 前端 `lint + build + test`、后端 `build + unit + integration tests`、PR CI 全绿。
8. Fast Refresh warnings 清零；Actions 无 Node 20 deprecation warning 或已记录无法消除的第三方原因。

## 六、明确不做

- 本 PR 不修改任何业务代码、测试代码、workflow 或部署配置。
- 不改变既有业务流程、业务 API 语义、权限模型和数据库结构。
- 不实现 PDA 布局重构；PDA 只保持既有浅色高对比作业框架。
- 不做业务数据全局搜索；顶部搜索仅覆盖有权限的菜单/页面注册项。
- 不做标签页拖动排序、固定标签、跨会话恢复、标签分组、标签颜色配置。
- 不新增用户中心、修改密码、通知中心等未定义契约的功能。
- 不把生产/失效日期缺陷混入第 5 批平台重构；应单独追踪并先复现定位。
- 不在本批引入第二套 UI 框架、状态管理库或 i18n 方案。

## 七、风险与控制

| 风险 | 控制 |
|---|---|
| 全局标签页与现有入库模块局部标签重复 | 规格明确只保留一层全局工作标签；入库模块内部业务视图标签保留，二者不得混用 |
| 页面保活导致状态污染或内存增长 | 以标签 key 去重、关闭释放、权限失效处理和最小保活范围作为实现验收 |
| 顶部导航替代侧边菜单后入口不可发现 | 固定菜单 ICON 常驻，菜单搜索仅索引有权限入口，键盘/焦点行为进入测试 |
| i18n 范围失控 | 前端只管 UI 文案，后端只管业务错误消息；枚举显示职责写入两侧规范 |
| 工程规范过宽导致不可执行 | 每条规范优先绑定目录、依赖方向、测试或 CI 检查；不能检查的规则标注为评审约束 |
| 非阻塞遗留混入平台批 | 生产/失效日期单独追踪；Actions/Fast Refresh 只作为 M5.2 治理项 |

## 八、评审关注点

1. 固定“标签页”ICON 的建议行为是打开标签总览，用于查找、切换和批量关闭；“菜单”ICON 打开全局导航面板。请确认是否符合预期。
2. 顶部菜单搜索本批只搜菜单/页面，不搜业务单据、物料和批次。
3. 标签页保活范围是否接受“当前会话内”：刷新或深链接只恢复当前标签，不恢复全部历史标签。
4. 用户菜单本批仅展示账号上下文与退出登录；个人中心等功能待契约定义。
5. 生产/失效日期问题是否同意后置为独立数据缺陷追踪。
