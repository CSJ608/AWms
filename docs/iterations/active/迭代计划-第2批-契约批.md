# 迭代计划 — 第2批：契约批（技术栈 + 数据模型 + API 契约 + 双向评审）

> 状态：**已定稿（2026-08-10，用户确认开工范围）**。本批不写业务代码，只产出可开工的契约。

## 目标

把第 1 批设计产物细化为可开工的契约：技术栈 ADR、数据模型、API 契约（主数据/入库链/库存/权限/标签解析/附件/打印/导入导出）、通用规范（响应/分页/错误码/i18n/鉴权）；执行**双向评审门禁**，锁定契约。

**明确不做**：不写业务代码；不做 ASN / 出库 / 盘点 / 冻结 / 预留 / HU / AGV 等后置功能的契约（只留概念位，不展开）。

## 需求清单

| ID | 需求 | 说明 | 验收（DoD） |
|---|---|---|---|
| C-01 | 技术栈 ADR-004 | 后端/前端/PDA/存储/打印/导入导出选型 | 用户确认 |

| C-04 | 通用规范 | 响应格式/分页/错误码/i18n/鉴权约定 | 契约评审通过 |

## 契约文件清单（docs/api/）

README（导航+通用规范）、认证权限、物料、仓库库位、批次、来源、入库单、收货（含质检/上架）、库存（含库位库存/流水/可用）、工作台（聚合）、标签解析（AWMS1）、附件（拍照）、打印、导入导出、枚举与错误码。

## 起草顺序（建议）

1. C-01 技术栈 ADR（本批第一步）
2. C-02 数据模型
3. C-04 通用规范先行（所有模块依赖）
4. C-03 分模块：主数据 → 入库链 → 库存 → 工作台 → 标签/附件/打印/导入导出
5. C-05 双向评审：前端 AI + 后端 AI 各出意见 → 人裁决 → 契约锁定

## 风险与假设

- **契约量大**：分模块起草、分模块评审锁定，避免一次性大评审。
- **PDA 打印/离线**：本期不做，契约不展开（打印走 Web 浏览器）。
- **附件存储**：本期本地文件存储 + 元数据表（云存储后置）。
- **数据量**：SKU ≤10 万、日单据 ≤2000、用户 ≤50——契约按此规模设计，不做过度优化。
