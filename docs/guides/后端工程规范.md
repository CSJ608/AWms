# 后端工程规范（AWms）

> 状态：**v1.1（2026-08-10，用户确认；新增 §3.1 主键 UUID v7，关联 ADR-006）**。
> 适用范围：后端 AI（Claude Code，工作区 C:\build\b）从第 3 批重做起，开发/测试/迁移/汇报全流程。
> 依据与优先级：**项目契约（docs/api/ 锁定） > 本规范 > 技能建议**；AGENTS.md、规章制度 §8.8、迭代计划同时有效。

## 0. 三条铁律

1. **契约先行**：docs/api/ 是前后端唯一依据；任何接口改动先走评审改契约，再改代码；禁止单方"未改契约"地实现偏差。
2. **测试为证**："已完成"以 git + 测试为准；测试必须**真实覆盖需求行为**（禁止"execute 没写库却标绿"这类假绿）。
3. **技能是知识，不是免责**：技能内容与契约冲突时以契约为准，并把冲突回报协调者；在汇报中说明使用了哪些技能。

## 2. 工程与解决方案架构

### 2.1 项目结构（保持四层，职责边界严格）

```
backend/
├─ AWms.slnx
├─ Directory.Build.props          # 统一 TFM(.NET 10)/LangVersion/Nullable/ImplicitUsings/TreatWarningsAsErrors
├─ Directory.Packages.props       # CPM：所有包版本集中管理
├─ global.json                    # SDK 锁定（.NET 10）
├─ AWms.Domain/                   # 实体/枚举/接口/DTO（record）；零外部依赖
├─ AWms.Infrastructure/           # EF Core DbContext/迁移/服务实现（实现 Domain 接口）
├─ AWms.Api/                      # Controllers/Middleware/Program.cs；只做 HTTP 适配，不含业务
└─ AWms.Tests/                    # 单元测试（服务/查询解析）
└─ AWms.IntegrationTests/         # 集成测试（WebApplicationFactory + Testcontainers PostgreSQL）
```

- 依赖方向：Api → Infrastructure → Domain；Domain 不得引用 Infrastructure/Api。
- 一个实体/接口/DTO 族一个文件，禁止一个文件塞多个类（相关 record 可同文件成组）。
- 命名空间按功能模块组织（如 `AWms.Infrastructure.Services`、`AWms.Api.Controllers`）。

### 2.2 装配与配置

- DI：用 `IServiceCollection.AddXxx(...)` 扩展方法按模块组织；Program.cs 只做装配，不写注册细节（microsoft-extensions-dependency-injection 技能）。
- 配置：强类型 Options（IOptions<T>）+ appsettings；连接串/密钥走 user-secrets / 环境变量，不进 git。
- 中间件顺序：异常处理 → CORS → 认证 → 授权 → 路由/端点（dotnet-webapi 技能）。
- 日志：内置 ILogger + 结构化字段；不 Console.WriteLine。

### 2.3 错误与响应（统一 envelope）

- 所有响应 `ApiResponse<T>{ code, message, data }`；HTTP 状态码按契约（200/201/204/400/401/403/404/409/422/500）。
- 业务错误用**契约错误码常量**（如 MATERIAL_CODE_DUPLICATED），禁止散落魔法字符串；错误码→HTTP 状态映射集中一张表。
- 控制器不裸 catch；业务异常由异常中间件统一转 envelope；捕获异常时不得吞掉上下文。
- 参数校验在服务层/端点层显式完成，白名单外一律 400 VALIDATION_ERROR（不是静默忽略）。

### 2.4 幂等 / 事务 / 异步

- 写操作支持 Idempotency-Key：同 key 重复请求返回首次结果（含错误响应），记录 TTL（24h），与业务同事务。
- 事务：跨表写操作显式 `IDbContextTransaction`；读多写少不滥用事务。
- 异步：所有 IO 方法 async/await；导出任务必须**异步执行**（任务创建返回 PROCESSING → 后台生成 → DONE），不允许请求内同步生成。
- 时间：统一 UTC（DateTimeKind.Utc）；入库前统一转换。

### 2.5 认证与权限

- JWT Bearer + Argon2id 密码哈希；登录响应**严格按契约**：`{ token, expiresAt, user{...}, permissions, menus:{ web, pda } }`。
- refresh：允许"过期 token 换新"（针对 refresh 端点配置 ValidateLifetime 例外或自定义 JwtBearerEvents），前端 401 静默刷新才能工作。
- 权限：RequirePermission 过滤器 + 模块注册表（种子）；users/roles/permissions/logout/me 端点按契约补齐。
- 密码哈希种子：不允许占位哈希进生产种子；管理员初始密码用环境变量注入 + 首启重置，且重置逻辑要有测试。

## 3. 数据访问与迁移规范（重做重点）

- **只允许 EF Core Migrations**：禁止 EnsureCreated/EnsureDeleted；禁止对已有表 DROP/ALTER COLUMN（本批为全新库，但流程从第一天按迁移走）。
- 迁移工作流：
  1. 改模型 → `dotnet ef migrations add <Name>`（Infrastructure 项目）；
  2. **人工 review 生成的 SQL**（协调者复验时逐条看）；
  3. 本地/集成测试环境 `dotnet ef database update` 应用；
  4. 迁移文件随代码提交，不删除已提交迁移。
- PostgreSQL + Npgsql：decimal 用 18,4；UUID 主键；时间 timestamptz。

### 3.1 主键与 UUID（ADR-006）

- 主键一律 `Guid`（PG 类型 `uuid`），**值生成交给 EF/Npgsql 默认（UUID v7，时间有序）**；Npgsql EF 提供程序 9.0+ 已默认对 Guid 主键生成 v7。
- **禁止对主键手动 `Guid.NewGuid()`**（会退回 v4、破坏索引局部性）；确需显式生成时用 `Guid.CreateVersion7()`（.NET 9+ 内置）。
- 实体 `Id` 属性不写初始化器（保持 `Guid.Empty` 让 EF 生成）；种子数据用固定 GUID 常量（HasData）。
- 数据库侧可选：PostgreSQL ≥18 可用 `HasDefaultValueSql("uuidv7()")` 兜底；PG<18 不依赖数据库函数（客户端生成即可），集成测试任意 PG 16/17/18 均可。
- 业务可见编号（物料编码/批次号/单据号）仍走编号服务（通用规范 2.9），UUID 仅内部主键、不暴露给用户。
- 索引：唯一约束 HasIndex().IsUnique()；外键与高频筛选字段建索引；批次 (materialId, batchNo) 唯一索引。
- 查询：只读查询 AsNoTracking；避免 N+1（Include 按需、query splitting）；分页必须 Skip/Take 且 order 稳定；filter/sort 一律白名单+参数化。
- 并发：原子自增（编号服务）用 SQL `UPDATE ... RETURNING` 行锁实现；需要乐观并发时用 rowversion。
- 种子：HasData 只放稳定基础数据（角色/权限/模块/菜单/管理员）；业务演示种子走独立 Seed 服务（仅开发环境）。

## 4. API 设计规范（重做后端点形态）

- 控制器薄、服务层厚；DTO 与契约字段一一对应，**禁止 Entity 直出**。
- 端点形态（通用规范 2.10 v1.9）：
  - 标准列表查询：`POST /api/{resource}/search`，body `{ keyword?, 固定参数..., filter?, sort?, page?, pageSize? }`；
  - 引用选择器快捷搜索：`GET /api/{resource}?keyword=&pageSize=`（≤10）；
  - 详情：`GET /api/{resource}/{id}`；
  - 写操作：`POST/PUT/DELETE`，带 Idempotency-Key（写操作）。
- filter DSL：操作符全集 eq/neq/contains/startsWith/in/notIn/gt/gte/lt/lte/between/isNull/isNotNull **全部实现**；字段/操作符/排序白名单外 → 400；数值/日期比较必须用正确 CLR 类型构建表达式（禁止 string→decimal 的 Expression.Convert）。
- 分页：pageSize=0 全量仅限契约声明资源；默认 page=1, pageSize=20。
- OpenAPI：启用 OpenAPI 元数据；每个端点提供 .http 冒烟样例（dotnet-webapi 技能）。

## 5. 测试规范（硬门槛）

### 5.1 分层策略

| 层 | 工具 | 覆盖 |
|---|---|---|
| 单元测试 | xUnit + InMemory/纯逻辑 | 服务逻辑、查询解析、编号、幂等、导入校验（不依赖真实 DB 的纯逻辑） |
| 集成测试 | WebApplicationFactory + Testcontainers PostgreSQL（真实迁移） | API 全链路：认证/CRUD/导入导出/权限/错误码/幂等 |
| 契约测试 | 集成测试内断言 envelope/状态码/错误码 | 与 docs/api/ 逐条对齐 |

### 5.2 TDD 流程

1. 对每个 B-xx 需求先写**失败**测试（行为级：Given-When-Then）；
2. 最小实现使测试绿；
3. 重构；不得为了绿而删断言或跳过行为。

### 5.3 必测清单（重做验收对照）

| 需求 | 必须有的测试 |
|---|---|
| B-01 | build 0 error 0 warning；集成测试启动即应用全部迁移（迁移可应用） |
| B-02 | 登录成功/密码错误/停用；**refresh 用过期 token 换新**；LoginResponse 契约形状；users/roles/permissions CRUD + 引用保护；菜单/权限过滤 |
| B-03 | **并发取号**（如 50~100 并行无重复/无异常）；**耗尽抛 NUMBER_EXHAUSTED**；BATCH 格式 260810001、TXN_GROUP 15 位、IMPORT_TASK 格式 |
| B-04 | 白名单外字段/操作符/排序 → 400；in/notIn/between/isNull 生效；注入攻击（字段名/操作符/排序注入）被拒；数值/日期/枚举筛选正确 |
| B-05 | 物料/仓库/库位/来源 CRUD + keyword/searchCode；**重复码 409**；删除引用保护（事务内）；批次查询/详情 |
| B-06 | precheck 明细 ≤200 inline；重复码（文件内+库中）报错；canExecute 语义；**execute 真实入库且同事务重校验**；导出遵循 filter/sort/pageSize；任务 PROCESSING→DONE |
| B-07 | 同 key 并发/重复写请求返回首次结果；TTL 过期后可重放 |
| B-08 | 全绿；覆盖率报告（coverage-analysis），核心服务行覆盖 ≥70%；CRAP 热点不新增 |

### 5.4 测试卫生

- 不 sleep、不依赖真实时钟（注入 ITimeProvider）；断言业务结果与契约错误码，不测实现细节。
- 测试命名：`方法_场景_期望`（如 `ExecuteAsync_干净文件_真实入库并返回DONE`）。
- 集成测试用 Testcontainers 时，fixture 每个测试类一个容器实例；迁移在容器启动时应用。
- 提交前必须 `dotnet test` 全绿（含集成测试）；覆盖率不达标视为未完成。

## 6. 开发流程（重做批次执行顺序）

1. **开工**：读 AGENTS.md → 交接快照 → 迭代计划第 3 批 → docs/api/ 全套 → 本规范 → 相关技能 frontmatter。
2. **工程骨架**（B-01）：slnx + 4 项目 + Directory.Build.props + CPM + global.json + 迁移基建（不 EnsureCreated）。
3. **逐项 TDD 实现** B-02~B-08：先测后码；每项完成即 `dotnet test`。
4. **迁移**：模型变更即生成迁移，review SQL。
5. **自测**：build（0 error 0 warning）→ 单元+集成全绿 → 覆盖率报告。
6. **汇报**：按 §8.8 六项模板；完成范围逐条对照需求；测试结果给命令与用例数；偏差/遗留如实；注明使用的技能。
7. **提交**：Conventional Commits + 中文描述，分项提交（feat:/test:/docs:/fix:）。
