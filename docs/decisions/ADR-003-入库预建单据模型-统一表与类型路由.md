# ADR-003：入库预建单据模型——统一表 + 类型路由（草案）

> 状态：**草案（2026-08-09，待用户确认）**。确认后改为已采纳。

## 背景

收货场景 2/4 需要扫单据二维码打开预建单据。单据二维码带"单据类型 + 单号"。需要决定存储模型：
所有入库单据放同一张表（类型字段区分），还是不同单据类型各一张表（解析时按类型查对应表）。

本期入库来源：采购到货、生产退料、其他入库。数量一致性策略（严格/宽松）挂在来源单据类型上。

## 决策

1. **本期"入库预建单"统一一张表**，带类型字段 ty（PO=采购 / PR=生产退料 / OT=其他）；
   行结构统一（物料/数量/批次/来源信息），字段差异用可空列吸收。
2. **单据二维码 = 类型 + 单号（+仓库）**；解析层按"类型 → 单据服务/仓储"**路由**。
   本期所有类型都指向统一表实现；未来某类型独立成表或接入 ERP 时，只改路由注册表，
   **PDA 扫描解析代码不变**。
3. **收货单（执行单）独立且统一**，通过"来源单据类型 + 来源单号"引用预建单（无预建单场景该引用为空）。
4. 数量一致性策略（严格/宽松）挂在"来源单据类型"上，类型是稳定枚举。

## 影响

- 概念设计需包含：入库预建单（来源单据）、收货单（执行单据）、来源单据类型枚举。
- 契约的收货接口带 sourceDocType + sourceDocNo；单据查询接口按 type+docNo 路由。
- 未来拆表/接 ERP 的改动被限制在"类型 → 单据服务"注册表内。

## 备选方案

- **每类型独立表**：字段各自精确、约束强；但本期三种来源字段差异极小，分表带来重复 CRUD 与
  解析分支，原型验证成本高。→ 否决（本期），保留"类型路由"作为未来拆分点。
- **超级大表（含采购单/ASN 等全部单据）**：把未来复杂度提前，宽表难维护。→ 否决。
