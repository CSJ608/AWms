# ADR-005：认证方式——本期内部账号 + Bearer token，不做 OAuth（草案）

> 状态：**草案（2026-08-10，待用户确认）**。确认后改为已采纳。

## 背景

内部原型 WMS：50 用户、独立账号、Web+PDA 同一前端。已确认：用户名+密码登录、Bearer token、401 静默刷新重放。
未来可能：接入企业统一身份（OIDC/IdP）、对接外部系统（AGV 调度/ERP，服务间认证）。

## 分析

| OAuth 用途 | 场景 | 本期是否需要 |
|---|---|---|
| 授权码模式（第三方应用代表用户） | 外部 App 访问用户数据 | ❌ 无第三方应用 |
| OIDC（SSO/身份联邦） | 企业统一 IdP 登录 | ⏳ 未来（接入 IdP 时用 OIDC，不自研） |
| 客户端凭证/API Key（服务间） | 对接 AGV/ERP | ⏳ 未来（对接时再定） |

- 标准 OAuth 授权码流程（客户端注册/重定向/授权服务器）对内部系统是纯成本，PDA 端无浏览器重定向便利。
- "用户名+密码 → Bearer token → 静默刷新重放"已满足本期全部需求。

## 决策（建议）

1. **本期**：用户名+密码 → Bearer token（JWT 或等值，含 sub/exp/roles/permissions）；login/refresh/me/logout 接口形态（已定，认证权限契约 v0.1）。
2. **密码安全**：哈希存储（Argon2id/bcrypt）；token 有效期 + refresh；管理员重置密码，无自助注册。
3. **扩展点（本期不做）**：
   - 未来 SSO：用 **OIDC** 接入企业 IdP——前端只改登录交互（跳 IdP），Bearer 接口形态不变；
   - 未来服务间对接：**client credentials / API Key**，不影响用户认证。
4. 前端/契约不绑定具体 token 实现（仅 Bearer 语义），为平滑替换留缝。

## 影响

- 认证权限契约 v0.1 无需改动（已按此形态设计）。
- 后端实现注意：token 载荷含 sub/exp/roles/permissions 即可，不必引入 OAuth 服务器。

## 备选

- 本期实现标准 OAuth 授权码：否决（过度设计，无第三方应用，PDA 不便）。
- 自研 OAuth 服务器：否决（维护成本高，无收益）。
