# ADR-001：框架先行——登录/用户/角色/权限/菜单早期内置

> 状态：已采纳（2026-08-09）

## 背景

旧项目 MWms 早期未确定权限与菜单框架，操作人以占位符（"王仓管"）出现，后续增加功能模块时感觉很不方便。用户明确要求：**早期就确定框架**，让后续加模块顺畅。

## 决策

1. **v1 即内置身份与权限框架**：登录、用户、角色、权限、菜单，作为系统基础模块，不后置。
2. **权限分层**：路由权限（能否进入某模块）→ 菜单权限（界面可见性）→ 操作权限（按钮/动作，如查看/新增/编辑/删除/导入/导出/打印）；查看与操作权限分开。
3. **模块化单体内置模块注册表**：每个业务模块声明自己的菜单、路由、权限点；菜单由注册表驱动，新增模块 = 新增一个注册项，不改框架。
4. **默认单体架构**：拆子系统必须拿出证据。

## 影响

- 第 1 批设计批必须包含"框架设计"（模块注册、权限模型、菜单模型）。
- 契约层需包含身份/权限相关契约。
- 前端路由/菜单/权限控制由注册表驱动，页面不写死导航。

## 备选方案

- 权限后置（MWms 做法）：先做业务再补权限。**否决**：用户已明确感受过其不便。
