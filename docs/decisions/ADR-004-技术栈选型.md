# ADR-004：技术栈选型（草案）

> 状态：**草案（2026-08-10，待用户确认）**。确认后改为已采纳。

## 背景

第 2 批（契约批）需要先锁定技术栈，契约与实现才可据此展开。
本机环境：.NET SDK 9.0 / 10.0（10 为 LTS）、Node 26、pnpm 11。

## 决策（建议）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **.NET 10（LTS）+ ASP.NET Core Web API + EF Core** | 本机已装；与 TemplateFrame/Wms4 同为 .NET，便于参考导入导出/打印思路 |
| 数据库 | **PostgreSQL** | MWms 已验证；测试环境 docker compose 编排 |
| 前端 Web | **React 19 + Vite + TypeScript strict + Tailwind v4 + shadcn/ui** | 沿用已验证基线（星云/MWms），中性简洁视觉（D-05 定稿） |
| PDA | **同一前端代码库的移动端 Web（PWA）** | 单一代码库维护成本最低；PDA 扫描枪=键盘输入模式，Web 天然支持；离线能力后置 |
| 附件（拍照） | 本地文件存储 + 数据库元数据 | 原型够用；云存储/MinIO 后置 |
| 打印 | 本期 **浏览器打印（PDF）** + 内置模板；PDA 打印后置 | 先解决"能打"，再解决"在哪打"；打印服务后续按 TemplateFrame 思路演进 |
| 导入导出 | 后端平台能力（CSV/Excel：模板 + 两阶段校验 + 失败明细），参考 TemplateFrame.Excel 思路，**自研** | 复用其"契约驱动"思想，不照搬代码 |

## 备选

- PDA 原生 App / 独立 PDA 项目：成本高、双份维护 → 否决（本期）。
- 后端 Java/Spring：团队无既有资产 → 否决。
- 打印接 TemplateFrame 全套：等打印需求明确（第 5 批前）再评估，本期浏览器打印。

## 影响

- 前端单仓双端（Web + PDA 布局），路由/布局按端区分。
- 契约中附件、打印、导入导出按本期选型定义接口。
