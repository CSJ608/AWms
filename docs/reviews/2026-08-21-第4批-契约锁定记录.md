## 三、成功响应契约缺口裁决

完工审核发现锁定 v0.5 未显式规定以下三个端点的成功 HTTP status 与响应 DTO。2026-08-21，契约责任人正式裁决并先回写标准契约：

| 端点 | 成功状态 | 统一 envelope `data` |
|---|---|---|
| `POST /api/receipt-lines/{lineId}/quality-check` | HTTP 200 | 完整 `Receipt` DTO |
| `POST /api/quality-checks/{checkId}/resolve` | HTTP 200 | 完整 `Receipt` DTO |
| `POST /api/putaway-records` | HTTP 201 | 完整 `Receipt` DTO |

- 三个端点均使用通用 `ApiResponse<Receipt>` envelope，不允许返回 204、`unknown` 或 `QualityExceptionItem` 作为成功结果。
- 本次仅补足既有业务动作的成功响应定义，不变更路径、方法、请求 DTO、状态机、错误码、权限或幂等规则。
- 前后端实现、PostgreSQL 集成测试及 MSW 以 `65ab25d` 为新的第 4 批契约基线；两个 feat 分支同步并取得测试证据后方可关闭完工审核 P2。
