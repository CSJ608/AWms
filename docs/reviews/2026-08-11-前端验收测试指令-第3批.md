# 前端验收测试指令 — 第3批（测试环境联调迭代）

> 出具人：协调者（Codex）｜日期：2026-08-11
> 适用：前端工作区（默认 C:\build\f）
> 依据：docs/iterations/active/第3批-验收测试计划.md（功能目标清单与本指令配套）

## 一、角色与纪律

- 你只负责**测试与汇报**：逐条验证功能目标，记录状态与证据。
- **不修改任何代码**（前端、后端、契约、docker 编排均不动）；发现问题只记录初步原因分析。
- 三态：✅ 通过 / ❌ 失败（附初步原因）/ ⛔ 阻塞（前置不满足）。
- 每项证据：URL、请求/响应（DevTools 或 API 工具）、截图、DB 查询（psql：`docker exec awms-test-db-1 psql -U awms -d awms_test`）。

## 二、测试环境

- 前端：http://localhost:8082（真实后端，VITE_USE_MOCK=false 已由部署保证；无需本地起服务）
- API：http://localhost:5081
- 账号：admin / Admin@2026Dev（口令在 deploy/.env，测试专用）
- 若页面异常，先 **Ctrl+F5 强刷**；仍异常再记录。

## 三、执行顺序（关键！）

1. **先做前置冒烟 A 组 + B 组**（登录/会话/路由/导航）。
2. 若 A1/A2 或 B2 无法通过 → **立即停止**，写《frontend/第3批-验收阻塞汇总.md》（精确复现：URL → 期望 → 实际 → 浏览器控制台错误 → 截图），回报协调者，**不要继续测后续组**。
3. 前置通过 → 按 C→J 顺序逐组测试；失败项记录但不阻塞（能进则继续）。
4. 全部测完 → 写《frontend/第3批-验收测试报告.md》。

## 四、重点关注（用户反馈路由跳转问题）

- 逐条验证 B 组；特别确认：
  - 登录后落地页是哪个 URL，是否 404；
  - 侧边栏 4 个菜单（工作台/入库/主数据/系统）逐个点击的实际表现；
  - 主数据 5 个页面（物料/仓库/库位/来源/批次）能否从菜单或 URL 直达。
- 协调者初步嫌疑：工作台(/)、入库(/inbound)、系统(/system) 前端无对应页面，点击会落应用内 404——请验证是否属实，并记录为“待裁决：未实现模块的菜单入口应如何表现（占位页/隐藏/禁用）”。

## 五、汇报文件

1. 《frontend/第3批-验收测试报告.md》：目标清单逐条 → 状态 / 证据 / 初步原因；末尾附待裁决问题清单。
2. （仅阻塞时）《frontend/第3批-验收阻塞汇总.md》：阻塞项精确复现 + 当前完成进度。

完成后 push 分支（或直接在工作区保留文件并回报协调者），由协调者复核、用户裁决下一步（修复迭代范围）。
