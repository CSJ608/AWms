## 三、后端缺陷/待裁决（抽查确认，需后端处理）

### 必须修复（P1，联调发现的真实缺陷）

- **Q1 错误响应 envelope 大小写不一致**：异常路径（ExceptionHandlerMiddleware 默认 JsonSerializer）输出 PascalCase，MVC/过滤器路径输出 camelCase。实测：
  - `POST /api/auth/login` 错密码 → 401 `{"Code":"LOGIN_FAILED","Message":"…","Data":null}`；
  - `POST /api/materials` 重复码 → 409 `{"Code":"MATERIAL_CODE_DUPLICATED",…}`；
  - `GET /api/meta/fields/users` 404 → `{"code":"NOT_FOUND",…}`（camelCase）——两套并存。
  - 影响：前端 `client.ts` 只认小写 `code`，PascalCase 错误的 code 退化为 UNKNOWN_ERROR，按 code 提示/静默语义失效（如重复码 409 toast 文案丢失）。
  - 修复建议：ExceptionHandlerMiddleware 序列化统一 camelCase（JsonNamingPolicy.CamelCase + UnsafeRelaxedJsonEscaping，与 IdempotencyFilter 一致），并加契约测试断言错误 envelope 键名。

- **Q6 JWT 密钥双来源不一致**：Program.cs 读 `Jwt:SecretKey` 或 `AWMS_JWT_SECRET`；TokenService 经 `IOptions<JwtOptions>` 只读 `Jwt:SecretKey`（appsettings 占位空）。实测（干净环境，仅注入 `AWMS_JWT_SECRET`，端口 5001）：
  - `POST /api/auth/login` → 500 `{"Code":"INTERNAL_ERROR",…}`，日志 `IDX10703: key length is zero`。
  - 影响：按《联调指令》只注入 `AWMS_JWT_SECRET` 即无法登录（联调时靠额外注入 `Jwt__SecretKey` 绕过）。
  - 修复建议：单一来源——Program.cs 在配置 JwtOptions 时把 `AWMS_JWT_SECRET` 回填到 `Jwt:SecretKey`（或 JwtOptions 读环境变量兜底），并补启动/登录测试（只注入 AWMS_JWT_SECRET 可登录）。

### 待裁决 / 应修复（P2/P3）

- **Q2（待裁决，P2）读端点无模块路由权限**：`GET /api/users`、`POST /{resource}/search`、`GET ?keyword=`、`GET {id}` 仅 `[Authorize]`，无 `route.<moduleCode>` 检查；OPERATOR 可读用户列表/物料列表。建议：读端点按资源挂 `route.<moduleCode>`（users→route.system、主数据→route.master-data），或由用户裁决“路由权限仅前端层”。
- **Q3（待裁决，P2）仓库/库位/来源操作权限码缺失/误用**：注册表无 `action.warehouse/location/source.*`；写端点误用 `action.material.create/edit/delete`（删除来源需“删除物料”权限）。建议：补注册表+种子（SUPERVISOR/SYSTEM_ADMIN）+前端接回；或本期删除这三个资源的操作级权限点（不可继续误用 material 码）。
- **Q4（应修复，P3）`GET /api/meta/fields/users` 未实现**（认证权限.md 声明）→ 404。建议：补实现（小）或从契约删除该行。
- **Q5（待裁决，P3）`GET /api/roles` 响应为数组**，契约未写明形态（认证权限.md 写了 page/pageSize）。建议：契约明确“本期数组即可”或后端补分页，二选一，需一致。
- （补充记录）`searchCode` 唯一性：后端有唯一约束，契约未写明 —— 建议契约物料/仓库库位/来源补一句（第 3 批小改）。
