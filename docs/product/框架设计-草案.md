# 框架设计：登录 / 权限 / 菜单 / 模块注册（草案 v0.1，D-03）

> 状态：**草案（2026-08-09，讨论中）**，第 1 批（设计批）D-03。
> 依据：ADR-001（框架先行，三级权限）、ADR-002（PDA/Web 双端）、愿景 v1.0（50 人内部原型）。

## 一、目标

1. 登录、用户、角色、权限、菜单在 v1 内置，不后置。
2. **新增功能模块 = 注册表加一项，框架不动**（回应"早期没定框架，后面加模块很不方便"）。
3. 同一套权限模型同时驱动 **Web 后台**（侧边栏菜单）与 **PDA 作业端**（作业入口）。

## 二、模块划分（本期）

| 模块 | 说明 | 端 |
|---|---|---|
| 系统基础 | 登录/用户/角色/权限/菜单/模块注册 | Web |
| 主数据 | 物料/仓库/库位/批次/来源（供应商/车间） | Web（PDA 只读引用） |
| 入库链 | 入库预建单 / 收货 / 质检 / 上架 | Web（单据管理）+ PDA（作业） |
| 库存 | 库存主体 / 物理库存 / 流水查询 | Web |
| 打印 | 收货回执 / 批次标签 / 库位标签（内置模板） | Web 管理 + PDA 触发 |
| 附件 | 收货拍照存储与查看 | PDA 拍照 + Web 查看 |
| 导入导出 | 主数据批量导入导出（平台能力） | Web |

## 三、权限模型（三级，ADR-001 落地）

- 用户 ↔ 角色（多对多）→ 权限点（多对多）。
- 权限点三类：
  1. **路由权限**：能否进入模块（如入库链）
  2. **菜单权限**：界面是否显示该菜单/入口（Web 侧边栏、PDA 主界面）
  3. **操作权限**：按钮/动作（查看 / 新增 / 编辑 / 删除 / 导入 / 导出 / 打印 / 作废 / 处理异常）
- **查看与操作分离**：默认授予查看权限；操作权限按角色分配。

## 四、模块注册表（菜单由注册驱动）

每个模块声明：

- moduleCode / moduleName
- webMenus：Web 端菜单项（分组 / 路径 / 图标）
- pdaEntries：PDA 端作业入口（收货 / 质检 / 上架）
- permissionPoints：权限点清单（code / 名称 / 建议默认角色）
- 路由与菜单由注册表生成，页面代码不写死导航

**菜单渲染**：用户角色 → 权限点 → 过滤注册表 → 生成 Web 侧边栏 / PDA 主界面入口。
**新增模块**：注册表加一项 + 实现页面/服务；框架代码不动。

## 五、登录与会话

- 用户名 + 密码；token 会话；无 SSO / 多因素（内部原型）。
- **操作人身份进入流水（"谁"）与审计**。
- 初始角色：系统管理员 / 仓管 / 作业员。

## 六、数据模型草图（概念级，契约批细化）

```
User(id, username, name, passwordHash, status)
Role(id, code, name)
Permission(id, code, name, category)          # category: route / menu / action
Module(id, code, name)
MenuEntry(id, moduleId, code, path, group, surface, sort)  # surface: web / pda
UserRole(userId, roleId)
RolePermission(roleId, permissionId)
```
