# 愿景 v1.0（已定稿 2026-08-09）

> 状态：**已定稿**。后续变更走评审，变更记录见文末。

## 一句话

为仓库现场作业人员打造一套**"打开就知道下一步干什么、做错会拦住你、做完可追溯"**的 WMS 操作台。

## 为谁

| 角色 | 一句话职责 | 典型痛点 |
|---|---|---|
| 收货/质检/上架员 | 把到货变成可用的库存 | 高频录入、怕填错、单据多 |
| 拣货/发货员（后续） | 按出库单把货找出来发出去 | 怕找错货、怕漏发 |
| 仓管/主管 | 看库存、盯异常、组织盘点 | 账实不符、状态不透明 |
| 系统管理员 | 维护主数据与权限 | 配置分散、难审计 |

## 解决什么问题

1. 现场作业靠经验与纸质单据，效率低、易错、难追溯。
2. 库存账目不透明：账实不符、状态不清、说不清每一笔变动。
3. 管理层看不到"现在仓库里正在发生什么、有什么待办"。

## 已确认的关键决策（2026-08-09 用户拍板）

1. **定位**：内部原型，用于验证新的概念设计是否可行；不支持多组织，支持多仓库。
2. **规模**：SKU ≤ 10 万；日单据 ≤ 2000；使用用户 ≤ 50 人。
3. **作业终端**：考虑 PDA，不考虑扫码枪。**目标：一线操作人员只用 PDA 就完成全部操作，尽可能减少手动输入（扫码为主要输入）**。
4. **仓型**：支持人工管理仓与 AGV 管理仓。AGV 任务派发最后考虑；**本期以人工仓为主，设计上预留 AGV 适配**（如库位可达性、任务执行主体等概念，详见 ADR-002）。
5. **框架先行**：早期就确定登录/用户/角色/权限/菜单框架，避免后续加功能模块不便（详见 ADR-001）。
6. **路线从收货开始**：先做收货链（收货 → 质检 → 上架），再做"查阅收货库存"（库存账目查询）；其他事项排在后面。
7. **服务于收货的设计**（本期范围的一部分）：
   - 基础数据维护，**要考虑导入与导出**；
   - 管理追溯：**收货拍照**，未来可导出查看；
   - **单据打印**：规范收货流程，未来也适用于出库发货流程。

## 成功长什么样（信号，可观察）

- 完成一次收货/质检/上架的高频操作，点击或按键次数显著少于旧方式；一线作业在 PDA 上即可完成，无需回电脑录入。
- 任何一笔库存变动，都能回答：谁、何时、从哪到哪、为什么（流水可追溯）。
- 盘点账实一致率稳定达到目标（例如 100%）。
- 新员工在短时间培训后能独立完成一条完整作业流。
- 系统永远不会让用户"做了一半才发现做错"（错误防呆 + 可撤销）。

## 明确不做（边界）

- 不做财务/计费/成本核算。
- 不做电商/订单系统对接（出库先手工建单）。
- 不做多租户 SaaS。
- 本期不做 AGV 调度执行（只做概念与契约预留）。
- 复杂能力（波次拣货、越库、跨仓调拨、自动化设备）本期不做，列为后续。

## 体验原则（不可妥协）

1. 高频操作一次做对：默认值、级联、防呆、可撤销。
2. 状态永远可见：任何主体/单据的状态一眼可读，不靠记忆。
3. 错误可恢复：失败不产生脏数据，提示具体、可行动。
4. 现场优先：大字、快响应、少滚动、PDA 扫码优先、单手可操作。
