## ④ 契约适配与问题清单（F-R2 终裁后）

**传输方式已按终裁对齐（README 2.10 v1.9/v2.1 + 各资源契约）**：

1. **标准列表查询统一 POST /api/{resource}/search**：物料/仓库/来源/批次 → `/api/{resource}/search`；库位（嵌套）→ `/api/warehouses/{warehouseId}/locations/search`；物料批次（嵌套）→ `/api/materials/{materialId}/batches/search`。body：`{ keyword?, 固定参数..., filter?, sort?, page?, pageSize? }`，filter/sort 不再序列化进 URL query（`queryToParams` 移除，改为 `toSearchBody`）。
2. **GET /api/{resource}?keyword=&pageSize= 仅作引用选择器快捷搜索**：新增 `apiQuickSearch*`（pageSize 默认 10），ReferencePicker 快捷搜索改走 GET；完整选择弹窗/回显扫描走 POST /search。
3. **默认排序（v2.1）**：mock 服务端按契约补默认排序——主数据（物料/仓库/库位/来源）`code asc`，时间性列表（批次）`createdAt DESC 最新在前`；批次页默认排序由 `batchNo asc` 改为 `createdAt desc`。
4. **固定参数按契约 search body 行对齐**：仓库/来源的 code/name 不再是固定参数（契约 body 行未声明），筛选自动落 filter DSL（字段白名单含 code/name，合法）。

**契约问题清单（docs/api/ 只读，未改动；供协调者确认）**：

1. **仓库库位 v0.3 / 来源 v0.3 固定参数不一致**：两契约 search body 行仅声明 `{ keyword?, status?, ... }` / `{ keyword?, type?, status?, ... }`，未列 code/name 固定参数；但 README 2.10 写「各接口保留常用筛选（code/name 的 eq/contains、日期区间、状态等）」。前端已按各资源 body 行严格对齐（code/name 走 filter DSL）。请协调者确认是否在仓库/来源契约 body 行补上 code/name（与物料一致）。
2. **嵌套批次端点默认排序未声明**：`POST /api/materials/{materialId}/batches/search`（批次 v0.6）未写明默认排序；前端按时间性列表 `createdAt DESC` 处理（与 `/api/batches/search` 一致），建议契约补一句。
3. （原有，非阻塞）物料/仓库/来源无 `GET /api/{resource}/{id}` 端点，ReferencePicker 单选回显用列表扫描（pageSize=100）兜底；批次有 by-id 端点。可后续统一补 by-id 端点。

### F-R1 修复：Node 26 测试可复现（阻塞项）

**根因**：Node 26 自带实验性全局 `localStorage`（未加 `--localstorage-file` 时为 undefined），遮蔽 jsdom 注入版；且 vitest `populateGlobal` 对「已存在于 Node 全局的 key」跳过 jsdom 注入 → Node 26 下 `window.localStorage` 为 undefined，裸访问 `localStorage.getItem` 直接抛 TypeError（9 文件 0 用例），修复守卫后会话持久化仍会静默失效（401 全挂）。

**修复内容**：

1. `src/lib/storage.ts` 新增 `getLocalStorage()`：`window.localStorage` + `typeof window`/try-catch 守卫（SSR/隐私模式安全）；
2. `src/i18n/index.ts`、`src/platform/auth/session-store.ts` 全部改走守卫（session-store 5 处裸用一并加固）；`src/test/setup.ts` afterEach 改 `window.localStorage?.clear()`；
3. **测试 setup 统一 stub**：Node 26 下 `window.localStorage` 缺失时注入内存 Storage 实现（vitest 跳过了 jsdom 注入，需显式补）——这是"测试绿可复现"的关键，Node 22 走 jsdom 原生不受影响；
4. **版本锁定**：package.json 加 `engines: { node: ">=22" }` + `packageManager: pnpm@11.10.0`，新增 `.nvmrc`（22）；
5. 配套修复：Node 26 内置 undici 严格 instanceof 校验导致 multipart 上传序列化失败（`request.formData()` 抛 "Content-Type was not one of multipart/form-data"）→ setup.ts fetch 包装层手动序列化 multipart，Node 22/26 同一路径。

**验证**：Node v22.23.2 与 v26.7.0 双环境 `pnpm build` / `pnpm lint` / `pnpm test` 全绿（57/57），不依赖任何 NODE_OPTIONS 补丁。
