## 一、逐项修复说明

### F-01（中）会话恢复回写旧 token → 多次 401/refresh —— commit `1fab006`

- `src/platform/auth/auth-context.tsx`：会话恢复改为用 `apiMe()` 响应里的 `me.token / me.expiresAt` 构建并保存会话（后端 /me 返回请求头中的当前 token），删除对恢复前捕获的 `cached.token / cached.expiresAt` 的引用。
- mock 对齐真实后端行为（`src/mocks/handlers.ts`）：`/auth/refresh` 每次换发新 token（`mock-token-<user>#<轮次>`，`tokenUsername` 解析时剥离轮次 nonce）；`/auth/me` 回显请求头中的当前 token——否则"me.token 与旧 token 不同"的守门场景无法构造。
- 新增 `src/platform/auth/auth-context.test.tsx`（2 例）：
  1. 预置已失效会话 → 渲染 App → `/auth/me` 401 → 单飞 refresh → 重放成功 → 断言 `sessionStore` 中 token == `me.token`（新 token `mock-token-admin#1`，非旧 `mock-token-admin`）；`refreshCount == 1`；随后直接调用列表接口成功且 `refreshCount` 仍为 1（无二次 refresh）。旧实现（回写 cached.token）在该用例下必失败。
  2. 坏 token（refresh 401）→ 会话清理回登录页。
- 同步更新 `src/platform/auth/refresh-queue.test.ts` 的 token 断言（`mock-token-admin` → `mock-token-admin#1`）。

### F-02（低）占位页（/、/inbound、/system）死胡同 —— commit `9f54d8d`

- `src/App.tsx`：三个占位页路由改为包 `AppLayout` 的嵌套路由（`<Route path="/" element={<RequireAuth><AppLayout/></RequireAuth>}>` + index/inbound/system 子路由），删除原独立 `RootRoute`（加载/未登录守卫由 RequireAuth 统一处理）。进入占位页后保留左侧菜单 + 顶部登出，不再只能浏览器后退。
- `src/modules/web/ModulePlaceholderPage.tsx`：`h-screen` → `h-full min-h-64`（适配 AppLayout 主区域，不溢出滚动）。
- mock 菜单注册表对齐真实后端四项（`src/mocks/seed.ts`）：新增 dashboard（path `/`，无权限码=所有登录用户可见）、inbound（`/inbound`，menu.inbound）、system（`/system`，menu.system）菜单条目，并补 route/menu 权限码到 seedPermissions（admin 全量、OPERATOR=工作台+入库、SUPERVISOR=工作台+入库+主数据，与协调者 C4① 裁决一致）。
- `src/App.test.tsx`：占位页断言适配新布局（侧边栏常驻 `sidebar-nav`），新增"从侧边栏菜单进占位页 → 仍有侧边栏 → 可返回主数据 → 工作台占位页同样可导航"用例。

### F-03（低）批控列布尔原文 true/false —— commit `4e8ab0c`

- `src/platform/table/columns.tsx`：`boolColumn` 单元格改为独立 `BoolCell` 组件（列工厂内禁调 hooks），渲染 ✓ + `t('common.yes')` / ✗ + `t('common.no')`（中英随语言），移除原 `aria-label="true/false"`。
- `src/modules/web/master/MaterialsPage.test.tsx`：新增用例断言 MAT-001（批控=true）行内显示「是」、MAT-002（false）行内显示「否」、页面无 `true/false` 原文；切英文后显示 Yes/No（用例内切回中文避免影响同文件后续用例）。

### F-04（低）导入任务状态 i18n key 原文泄漏 —— commit `f98e8d7`

- `src/platform/import-export/ImportExportDialog.tsx`：状态字段 `{enumLabelKey(...) ?? task.status}`（直接渲染 key 原文）→ `{t(enumLabelKey(...) ?? task.status)}`。zh/en 语言包已含 `enums.importTaskStatus.*`（校验中/校验完成/执行中/已完成/失败），无需新增 key。
- `src/platform/import-export/ImportExportDialog.test.tsx`：新增用例——precheck 后状态显示「校验完成」（PRECHECKED）、执行后显示「已完成」（DONE），全程 `queryByText(/enums\.importTaskStatus/)` 不存在（key 原文泄漏守门）。旧实现下该用例必失败。

### 待裁决⑥（UX）新建对话框打开时清空表单 —— commit `807c699`

- 实测确认缺陷存在（新增守门用例先红后绿）：4 个 FormDialog 原有 `values: useMemo(..., [editing, open])` 方案**未生效**——RHF `values` prop 对"内容相同的新对象"（`{...DEFAULT_VALUES}`）做深比较不触发 reset，且对话框关闭时内容不卸载（Radix Presence），表单状态跨次打开残留，与验收观察一致。
- 修复：4 个 FormDialog（物料/仓库/库位/来源）改为 `defaultValues` + 打开时显式 `form.reset()`：
  - `open && !editing` → 重置为默认值（新建清空）；
  - `open && editing` → 重置为行数据（编辑回填，不回填错乱）；
  - 依赖 `[open, editing, form]`。
- 新增 `src/modules/web/master/FormDialogs.test.tsx`（4 例，QueryClientProvider harness）：每对话框覆盖「新建打开字段为空 → 输入后关闭再新建仍为空 → 编辑态正确回填 → 编辑→新建切换清空」。
